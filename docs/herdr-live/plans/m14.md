# M14 plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** herdr's external-process plugin model (manifest, install/link, actions, event and
startup hooks, plugin panes, link handlers, keybinds, logs) on herdr-live, so herdr's own
example plugins run unmodified.

**Architecture:** `HerdrServer.Plugins.*` in herdr_server. Pure modules (Paths, Manifest,
Context, Env, Links) carry the rules; one GenServer `Plugins.Runtime` owns in-flight
commands (Erlang ports, like `HerdrReload.TestGate` and the M13 sound command), the log
ring, startup hooks and event hooks; `Plugins.Registry` owns `plugins.json`. Everything a
plugin does to the session goes back through the M12 API via `HERDR_BIN_PATH` (=
`bin/herdr-live`). No module from a plugin directory is ever loaded into the VM.

**Tech Stack:** Elixir 1.20 / OTP 29, `toml ~> 0.7` (already a dep), Jason, Ports.

**Spec:** milestones.md §M14; the M14 brief (scratchpad `m14-brief.md`, quoted in
results/m14.md); herdr reference `herdr-reference:docs/next/website/src/content/docs/plugins.mdx`
and `cli-reference.mdx` §Plugins; reference code `src/app/api/plugins/*.rs`,
`src/plugin_paths.rs`, `src/persist/plugin_registry.rs`, `src/api/schema/plugins.rs`.
Port behaviour, never code.

## Global Constraints

- BEAM plugins are out of scope (human ruling 2026-10-24): never `Code.*`/`:code.*` on plugin files.
- Paths are herdr's re-rooted at `herdr-live/` (M13's config rule): config base
  `${XDG_CONFIG_HOME:-$HOME/.config}/herdr-live`, state base `${XDG_STATE_HOME:-$HOME/.local/state}/herdr-live`.
  Registry `<config>/plugins.json`; managed GitHub checkouts `<config>/plugins/github-installations/<slug>-<hash12>/<n>`;
  plugin config dir `<config>/plugins/config/<enc(id)>`; plugin state dir `<state>/plugins/<enc(id)>`.
  `enc` = herdr's `plugin_config_path_component` (lowercase ascii, digits, `.`, `_`, `-` kept; every other byte `%XX`
  upper hex; trailing `.` → `%2E`; empty → `%plugin`). Overridable in tests by app env
  `config :herdr_server, :plugins, config_dir: ..., state_dir: ...`.
- herdr compatibility version for `min_herdr_version`: `"0.9.4"` (the reference tag's Cargo version).
- Command env (herdr contract, authoritative over caller `--env`): `HERDR_SOCKET_PATH`, `HERDR_BIN_PATH`, `HERDR_ENV=1`,
  `HERDR_PLUGIN_ID`, `HERDR_PLUGIN_ROOT`, `HERDR_PLUGIN_CONFIG_DIR`, `HERDR_PLUGIN_STATE_DIR`, `HERDR_PLUGIN_CONTEXT_JSON`,
  optional `HERDR_WORKSPACE_ID`, `HERDR_TAB_ID`, `HERDR_PANE_ID`, `HERDR_PLUGIN_ACTION_ID`, `HERDR_PLUGIN_EVENT`,
  `HERDR_PLUGIN_EVENT_JSON`, `HERDR_PLUGIN_ENTRYPOINT_ID`, `HERDR_PLUGIN_CLICKED_URL`, `HERDR_PLUGIN_LINK_HANDLER_ID`,
  `HERDR_PLUGIN_CLICK_MODIFIERS` (comma-joined, order shift,alt,ctrl); plus herdr-live's `HERDR_LIVE_BIN`, `HERDR_LIVE_API`.
  No other secret is added; the rest of the env is the VM's (as herdr: plugins inherit the user's env).
- Commands are argv, never through a shell; cwd = plugin root; output captured capped at 64 KiB per stream;
  at most 32 commands in flight; log ring of 200 records.
- API errors use only M12's codes (`invalid_params not_found not_available failed`); herdr's specific code goes in
  `data.reason` (e.g. `"plugin_manifest_parse_failed"`).
- No `herdr_scene` change is planned. Every Spec/Argv/Store change lands in Task 1 (SPEC_PUBLISHED).
- Shared files (`App.Store`, `Modal.Menu`, `Client.PointerIo`, `bin/herdr-live`, `application.ex`): small,
  self-contained additive edits only.
- Every GenServer callback begins `state = Map.merge(%Struct{}, state)`; `code_change/3` on Runtime.
- `just live-check` and `just maintenance-test` green before every commit that touches lib code.

## Review Focus

- A plugin command that never exits or floods stdout: Runtime stays responsive, output capped at 64 KiB, the 33rd command answers `failed` with reason `plugin_command_limit_reached` (Task 4 test).
- A corrupt or missing `plugins.json`, or a plugin whose manifest was deleted or broken after install: the server boots, the other plugins still run, that plugin lists with `error` set and cannot run, and one toast and one log line say why (Task 3 test).
- A plugin id like `../../x` or `CON.a` cannot escape the config/state dirs (Task 2 test on `Paths.encode/1`).
- A caller `--env HERDR_PANE_ID=p99` or `--env HERDR_PLUGIN_ID=evil` on `plugin pane open` does not override the authoritative values (Task 5 test).
- A manifest edited on disk after linking: the next invocation uses the new manifest without a restart (Task 4 test: Registry re-reads on each invoke).

- `Registry.entries() :: [entry]` reads `plugins.json` (herdr shape: JSON array of objects with `plugin_id`, `plugin_root`,

  `Registry.plugins() :: [plugin]` = entries merged with a fresh `Manifest.load/1` each call; a failed load gives the entry

  (read, apply, sort by id, atomic write: tmp file + rename, mode 0600, dir 0700). Serialised by `:global.trans({__MODULE__, self()}, ...)` — ponytail: no cross-process file lock; the CLI goes through the server.
  `Registry.find(id_or_source) :: {:ok, plugin} | :error`.
- `Command.run(argv, cwd, env, opts) :: %{exit_code: integer | nil, stdout: binary, stderr: binary, error: binary | nil}` —
  blocking, used by Install (build commands, git) and by Runtime inside a Task. Port `{:spawn_executable, exe}` with `:args`,
  `:cd`, `:env` (charlists), `:exit_status`, `:binary`, `:use_stdio`; stderr captured by spawning
  `/bin/sh -c 'exec "$0" "$@" 2>"$HERDR_LIVE_STDERR_FILE"'` with a tmp file under the plugin state dir — ponytail: sh wrapper for stderr, a NIF if Windows ever matters. `exe` resolved with `System.find_executable/1` (relative `./x` against cwd); not found → `error: "command not found: x"`. Output capped at 64 KiB per stream (`opts[:cap]`), `opts[:timeout_ms]` kills the OS pid (`kill -9`, TestGate's approach) and sets `error: "timed out"`.
- `Install.link(path, enabled?) :: {:ok, plugin} | {:error, reason, message}` (no build, as herdr).
- `Install.install(source, ref, yes?) :: {:ok, plugin} | {:error, reason, message} | {:error, "confirmation_required", message, preview}`.
  `source` is GitHub shorthand `owner/repo[/subdir...]` (cloned with `git clone --depth 1 [--branch ref] <base>owner/repo`,
  base from app env `:plugins, git_base:` default `"https://github.com/"`), or a local directory (absolute or starting
  `./`/`../`/`~`, copied with `File.cp_r/2`, `.git` excluded). Both go into a fresh `Paths.installations_dir(id)/<n>`;
  the manifest is validated before build; `preview = %{plugin_id, name, version, source, build: [argv], startup: [argv], actions, events, panes, link_handlers}`;
  build commands run in order with no plugin env (herdr), timeout 10 min; a failure aborts with
  `plugin_build_failed` and a message naming index, cwd, argv, exit status and capped output; installing over a linked
  plugin is refused (`plugin_install_over_link`). Previous installation dirs are kept (herdr keeps them for running
  commands) — ponytail: no cleanup of old installations; add herdr's lease cleanup when disk use shows.
- `Install.uninstall(target)` unregisters only (files kept, as herdr). enable/disable flip `enabled`.
- link/install create the config and state dirs (`Paths.ensure_user_dirs/1`).
- Alerts: `Plugins.Alert.show(text)` = `Store.request({Plugins.Alert, :effect, [text]})` returning

  (M13 toast path, plus `Logger.warning`). Put it in `plugins/alert.ex`.
