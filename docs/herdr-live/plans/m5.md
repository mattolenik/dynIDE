# M5 Kernel Restart Under Live Children Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `kill -9` of the VM or a `herdr-live kernel-restart` is a sub-second restart with every PTY master, child process (same pid) and terminal state preserved.

**Architecture:** A small Rust broker (`herdr_broker`) is the parent of every VM. The VM sends it a dup of each PTY master at pane open (SCM_RIGHTS) plus a periodic per-pane `HandoffState` blob, so the broker always holds the last reference and the last-known state. On VM death the broker promotes a warm standby VM and replays the held fds and blobs to it; on `kernel-restart` it boots a fresh VM, asks the old one to freeze and send final state, adopts into the new one, and only then releases the old one. Terminal state crosses as ghostty's own snapshot format (`ghostty_snapshot_encode`/`decoder`), which carries both screens, scrollback, modes, cursor, kitty keyboard state and parser continuation.

**Tech Stack:** Rust (root `rust-toolchain.toml`), `libc`, Rustler `=0.38.0`, `crates/ghostty-vt` (vendored libghostty-vt, Zig 0.16.0), OTP 29, Elixir 1.20.4, POSIX `sh`.

**Spec:** `docs/herdr-live/milestones.md` (M5, M6 metric row), `docs/herdr-live/design.md` ("The split", "Client protocol", "Supervision trees", "What hot reload does not cover"), `docs/herdr-live/results/m1.md` (kernel API, threads, SIGCHLD), `docs/herdr-live/results/m0.md` (launcher), `AGENTS.md`. ## Rulings fixed by this plan (all tasks)

These go into `results/m5.md` verbatim (Task 9). Implementers do not revisit them; if one is impossible, stop and report.

1. **Broker language:** Rust binary, crate `live/native/herdr_broker`. Shell or escript cannot send SCM_RIGHTS.
2. **Who spawns children:** the VM (M1 `Pty.spawn`, unchanged). After any restart the new VM is not the children's parent: orphans of a dead VM reparent to init/launchd, which reaps them. Adopted panes detect exit with `kqueue EVFILT_PROC NOTE_EXIT` (macOS) / `pidfd_open` + `poll` (Linux), report `{:exit, id, :unknown}` (status unknowable for a non-child), and never `waitpid`. SIGCHLD handling in the VM is unchanged (M1 reset to SIG_DFL). During a graceful window the old VM's waiter may still reap a child that exits; the new VM then sees the exit immediately.
3. **How fds reach the broker:** `Keeper.open` sends a `HOLD` frame with a dup of the master (CLOEXEC) synchronously before replying, so a `kill -9` after `open` returns cannot lose the pane. The broker holds the fd until `DROP` (sent by `Keeper.close`).
4. **Terminal state format:** ghostty snapshot (`ghostty_snapshot_encode_alloc` / `ghostty_snapshot_decoder_decode`), not ANSI replay. Continuation tracking is enabled on every kernel Vt (`GHOSTTY_TERMINAL_OPT_CONTINUATION_MAX_BYTES = 65536`) so a snapshot never fails mid-escape. A blob that fails to decode adopts the pane with an empty Vt (child alive, screen lost) and logs a warning.
5. **Snapshot cadence vs `kill -9` fidelity:** `Handoff.Snapshotter` sends `UPDATE` every 1000 ms for panes whose Vt gen, title, pwd or hidden flag changed. `kill -9` restores each pane's terminal as of its last snapshot (at most about 1 s old); output the dead VM had already read after that snapshot is lost from the screen, output still in the PTY buffer is read by the new VM, and input queued in the dead VM's writer is lost. Panes opened after their last snapshot restore from the `HOLD` blob (empty screen). Graceful `kernel-restart` restores exact state (frozen, then snapshotted).
6. **Pane-id continuity:** ids are preserved; the new Keeper sets `next_id = max(adopted ids) + 1`.
7. **How a VM learns its role:** env `HERDR_BROKER_SOCK` (path) and `HERDR_LIVE_GEN` (integer). Without `HERDR_BROKER_SOCK` (mix test, iex) the VM starts fresh with no broker. With it, the VM sends `HELLO` and blocks application start until the broker sends `FRESH` or `ADOPT`* + `ADOPT_END`. That lets a booted standby be promoted later.
8. **Warm standby:** the broker keeps one standby VM booted (started only after the primary is primary, never concurrently with a first-boot compile). Crash path promotes it; boot takes about 0.6 s, so without a standby the 1 s p95 target is not reachable. `kernel-restart` kills the standby and boots a fresh VM (the standby may carry the old NIF).
9. **Graceful sequence:** `CTL_RESTART` -> stop standby -> boot target VM -> `HELLO` -> `PREPARE` to old -> old freezes every pane (writer stops at a buffer boundary, reader stops, unwritten input becomes `pending_input`), sends final `UPDATE`s, then `PREPARED` -> broker sends held entries as `ADOPT` + `ADOPT_END{graceful}` -> new adopts, writes `pending_input` first, `RESTORED` -> broker sends `RELEASE` to old -> old marks ptys released (no SIGHUP on drop) and exits 0. Any failure before `RESTORED` (boot timeout, `PREPARED` timeout, target death, `RESTORED` timeout): SIGKILL the target, wait for it, send `THAW` to the old VM, report failure. No rollback after `RESTORED`.
10. **Input during the window:** ctl requests (and so the scripted typing loop) are queued in the broker from `PREPARE` until `RESTORED` and then forwarded in order to the new primary: delayed, never lost or reordered. In-VM writers that call `Pty.write` on a frozen pane are queued into `pending_input` until the final take, then get `{:error, :closed}`; M3 clients must stop sending on the `:begin` notice (contract in Task 6).
11. **Redraw nudge:** on the crash path only (`ADOPT_END` reason 1), panes whose restored Vt is on the alternate screen get a SIGWINCH via a rows-1/rows resize pair so full-screen apps repaint over the possibly stale snapshot. Shells on the primary screen are left alone (no duplicate prompts).
12. **Timeouts:** target `HELLO` 120 s (covers a kernel recompile during boot), `PREPARED` 5 s, `RESTORED` 5 s, old VM exit after `RELEASE` 5 s then SIGKILL, standby stop SIGTERM then SIGKILL after 2 s, broker shutdown SIGTERM to primary then SIGKILL after 15 s, socket send/recv of one frame 5 s (`SO_SNDTIMEO`/`SO_RCVTIMEO`).
13. **Crash with no standby, or adoption failure:** boot a new VM and adopt (3 attempts). After 3 failures call the disk-restore hook (`fallback_restore`, a stub that logs `handoff failed; disk restore not implemented (M8)`), then start a fresh VM and close the held fds.
14. **SIGTERM/SIGINT/SIGHUP to the broker:** clean stop, never a handoff. The primary gets SIGTERM (its normal shutdown SIGHUPs panes), the standby/target get SIGTERM then SIGKILL after 2 s, the broker removes its socket and exits 0.
15. **Generic fd holding:** the broker stores opaque entries keyed by a binary key (`"pane/<id>"` for panes) with 0..64 fds and an opaque blob. M2/M3/M16 can hold tty fds and sockets under their own key prefixes without broker changes. Entries not claimed in the new VM by the time it sends `RESTORED` are dropped.

## Wire protocol (binding for Tasks 1, 4, 5, 6, 7, 8)

Unix stream socket `<runtime_dir>/broker.sock`, mode 0600, in a 0700 runtime dir. Runtime dir is `$HERDR_LIVE_RUNTIME_DIR`, default `${XDG_RUNTIME_DIR:-${TMPDIR:-/tmp}}/herdr-live-<uid>`.

Frame: `len: u32 BE` (bytes after this field) | `kind: u8` | `nfds: u8` | body (`len - 2` bytes). The fds ride as one SCM_RIGHTS control message on the `sendmsg` that carries the first header byte. Limits: body <= 64 MiB, nfds <= 64. Integers are big-endian. `key` is `klen: u16 | key bytes`. `blob` is the rest of the body (opaque; ETF from Elixir).

| kind | dir | name | body | fds |
|---|---|---|---|---|
| 0x01 | vm->b | HELLO | `gen: u64, os_pid: u32` | 0 |
| 0x02 | vm->b | HOLD | `key, blob` (replaces an entry with the same key, closing its old fds) | 0..64 |
| 0x03 | vm->b | UPDATE | `key, blob` (blob only; unknown key ignored) | 0 |
| 0x04 | vm->b | DROP | `key` | 0 |
| 0x05 | vm->b | RESTORED | `count: u32` (entries claimed) | 0 |
| 0x06 | vm->b | PREPARED | empty (all final UPDATEs precede it on the stream) | 0 |
| 0x07 | vm->b | REPLY | `ref: u64, payload` | 0 |
| 0x41 | b->vm | FRESH | empty | 0 |
| 0x42 | b->vm | ADOPT | `key, blob` (one frame per held entry) | as held |
| 0x43 | b->vm | ADOPT_END | `count: u32, reason: u8` (0 graceful, 1 crash) | 0 |
| 0x44 | b->vm | PREPARE | empty | 0 |
| 0x45 | b->vm | RELEASE | empty | 0 |
| 0x46 | b->vm | THAW | empty | 0 |
| 0x47 | b->vm | REQUEST | `ref: u64, payload` | 0 |
| 0x81 | ctl->b | CTL_RESTART | empty | 0 |
| 0x82 | ctl->b | CTL_STATUS | empty | 0 |
| 0x83 | ctl->b | CTL_REQUEST | `payload` | 0 |
| 0xC1 | b->ctl | CTL_RESULT | `ok: u8 (1 ok, 0 failed), text (utf-8)` | 0 |
| 0xC2 | b->ctl | CTL_STATUS_REPLY | text: `key=value\n` lines | 0 |
| 0xC3 | b->ctl | CTL_REPLY | `payload` | 0 |

The first frame on a connection decides its role (HELLO: VM; 0x8x: ctl). A ctl connection may pipeline any number of frames; replies come back in request order. Status keys (all always present, `-` when none): `broker_pid primary_gen primary_pid standby_gen standby_pid standby_ready entries phase handoffs last_handoff_kind last_handoff_ms`. `phase` is `idle | booting | preparing | adopting | releasing | stopping`. `last_handoff_ms` is broker-measured: crash path from VM death detection to `RESTORED`; graceful from `PREPARE` sent to `RESTORED`.

ctl payloads are ETF (`:erlang.term_to_binary`) handled by `HerdrServer.Handoff.Ctl` (Task 6): `:ping -> :pong`; `{:open, %{cmd, args, cols, rows}}` (optional `env`, `cwd`, `max_scrollback` default 10_000_000) `-> {:ok, id} | {:error, term}`; `{:write, id, binary} -> :ok | {:error, term}`; `{:text, id} -> {:ok, binary} | :error` (`Vt.read_text(vt, :screen)`); `:panes -> [{id, os_pid}]`; `{:close, id} -> :ok`.

## HandoffState blob (binding for Tasks 6, 7, 8)

`:erlang.term_to_binary(%{v: 1, id: id, os_pid: pos_integer, cols: pos_integer, rows: pos_integer, cell_px: {w, h} | nil, max_scrollback: non_neg_integer, hidden: boolean, title: binary | nil, pwd: binary | nil, exited: nil | status, pending_input: binary, vt: binary | nil, taken_at: integer_ms})`. `vt` is the ghostty snapshot (nil in the `HOLD` blob). Keyboard flags, input modes (cursor keys, bracketed paste, mouse modes, kitty keyboard stack), cursor, both screens and scrollback are inside `vt`. A blob with `v != 1` or that fails `binary_to_term(bin, [:safe])` is treated as `vt: nil` with the HOLD-time metadata unavailable: the pane is skipped (fd closed) and logged.

## Review Focus

1. A child that exited (and whose pid may be recycled) before a handoff must never be signalled or watched by the new VM: blobs carry `exited`; Task 3/6 tests pin "adopt with exited set reports exit at once and `Pty.kill` is a no-op".
2. A child that does not read its input (full PTY buffer) during a graceful restart: freeze must not hang; unwritten bytes carry over as `pending_input` in order (Task 3 test `freeze_carries_unwritten_input`).
3. `kill -9` immediately after `Keeper.open` returns: the pane must survive (HOLD is synchronous; Task 6 test asserts the HOLD frame is sent before `open` replies, via a fake link socket).
4. Broker SIGTERM while a standby is still booting or during a handoff: clean exit 0, no orphan VM, no handoff (Task 8 smoke step).
5. Two handoffs back to back (crash, then crash again before a new standby is ready): the second takes the no-standby path and still preserves children (Task 8 bench runs 10+ consecutive kills, waiting only for `standby_ready=1`; plus one run that kills without waiting).

  - `Pty::release(&self)`: requires frozen; marks released so `Drop` sends no SIGHUP and no exit event is ever sent.
