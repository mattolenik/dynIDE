# M4 Live Reload and Rollback Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Saving a file under `live/apps/*/lib` recompiles its fan-out through Mix inside the running VM and loads it; a failing call at a `Reload.Guard` boundary rolls the responsible batch back synchronously with process state intact.

**Architecture:** `HerdrServer.Reload.*` in `herdr_server`. A `Watcher` (file_system) debounces saves into path batches for `Reload.Server`, a GenServer that runs `Reload.Compiler` (Mix incremental compile in-VM), diffs ebin beams against its cache of loaded binaries, records a `Batch` in a pure `Ring`, and loads via `Reload.Loader`. `Reload.Guard.run/4` is the only blanket catch: it runs editable code inline or in a deadline-bounded process, counts exercise in ETS, and on failure asks `Reload.Server` to roll back the attributed batch. `Reload.Notices` is a duplicate-key `Registry` for UI events. Phase 1 has no `App.*` dependency; phase 2 wires it into M3's GenServers.

**Tech Stack:** Elixir 1.20.4 / OTP 29, Mix (runtime, dev only), `file_system ~> 1.1` (already in `mix.lock`), ExUnit.

**Spec:** `docs/herdr-live/design.md` (Hot reload, State layout, Supervision trees), `docs/herdr-live/milestones.md` (M4, M3).

## Facts established before planning (OTP 29 / Elixir 1.20.4, verified by experiment)

1. `Mix.Task.rerun("compile")` returns `:noop` after the first run, because `compile.all` and the per-compiler tasks stay marked as run. Working recipe: `Mix.Task.reenable("compile")`, `Mix.Task.reenable("compile.all")`, `Mix.Task.reenable("compile.#{c}")` for each `c <- Mix.Tasks.Compile.compilers()`, then `Mix.Task.run("compile", ["--return-errors"])`. It returns `{:ok | :noop | :error, [Mix.Task.Compiler.Diagnostic.t()]}` and in the umbrella under `mix run` it recurses into all apps. A one-file edit in `herdr_scene` took ~240ms; the first call ~1.3s (warm-up).
2. Mix does not keep recompiled modules loaded, and it is not hands-off: for every stale module `Mix.Compilers.Elixir.remove_and_purge/2` deletes the beam and calls `:code.purge/1` + `:code.delete/1`. So (a) after compile the new code autoloads from disk on next call; (b) on the second recompile of a module, Mix's `:code.purge` **kills** any process still running the generation before (verified: a gen-1 receive loop dies on the 2nd compile).
3. On a compile error the stale modules stay deleted and their beams are gone: calls raise `UndefinedFunctionError`. "Compile error: nothing loads" therefore needs an explicit restore from the in-memory cache.
4. Mix's staleness check is `size changed or (mtime changed and digest changed)` with second-resolution mtimes. A same-size edit within the same second as the previous compile is a `:noop` (verified). Fix: track the mtime each batch path had when compiled; if a path's current mtime equals it, set the file's mtime to `mtime - 1` before compiling.
5. `:code.load_binary/3` on a module whose current code Mix deleted succeeds (old slot untouched); on a module with both current and old code it returns `{:error, :not_purged}`.

## Review Focus

- Linux CI has no `inotify-tools`: `FileSystem` fails to start; the Watcher must log a warning and return `:ignore`, never crash app boot or the launcher smoke (Task 7 test: start Watcher with a backend that fails, assert `:ignore`).
- Two saves of the same file within one second with the same byte size must both be compiled (Task 4 test `same-second same-size edit is compiled`).

### Task 4: Compiler

**Files:**
- Create: `reload/compiler.ex`
- Test: `test/reload/compiler_test.exs` (`async: false`, `use HerdrServer.ReloadCase`)

**Interfaces:**
- Consumes: `Loader.purge_old/2`, `Loader.load/3`, `ReloadCase`.
- Produces:
  - `Compiler.ebin_dirs(opts) :: %{app => dir}` for the umbrella apps (or the single project app), via `Mix.Project.apps_paths/0` / `config[:app]` and `Mix.Project.build_path/0`; deps excluded. `opts[:project_dir]` (nil = current project) wraps every Mix call in `Mix.Project.in_project(app, dir, ...)`; `opts[:app]` names it.
  - `Compiler.snapshot(opts) :: %{module => binary}` reads every beam in `ebin_dirs`.
  - `Compiler.compile(cache :: %{module => binary}, paths :: [Path.t()], mtimes :: %{Path.t() => integer}, opts) :: {:ok, %{changed: %{module => binary}, removed: [module], previous: %{module => binary | nil}, diagnostics: list, mtimes: map}} | {:error, diagnostics, mtimes} | {:blocked, module, [pid_info]}`. Steps in order:
    1. Pre-sweep: for every module in `cache` with `:erlang.check_old_code/1` true, `Loader.purge_old(mod, allowlist: opts[:allowlist])`; first `{:blocked, holders}` aborts with `{:blocked, mod, holders}` before Mix runs (Fact 2: Mix would hard-purge it). 
    2. mtime fix (Fact 4) for `paths` using `mtimes` (posix seconds per path as of its last compile); returns updated `mtimes` with each path's mtime after compile.
    3. Record `loaded_before = for {m, _} <- cache, :code.is_loaded(m), do: m`; `t0` = posix seconds.
    4. Run Mix (Fact 1 recipe). Wrap with `Mix.shell(Mix.Shell.Quiet)` restored after.
    5. On `{:error, diags}`: for every `m in loaded_before` now not loaded, `:code.load_binary(m, path, cache[m])` (Fact 3); return `{:error, diags, mtimes}`.
    6. Diff: beams with mtime ≥ `t0 - 1` whose bytes differ from `cache` → `changed`; cache modules whose beam file is gone → `removed`; `previous = Map.take(cache, changed ++ removed)` with `nil` for new modules. Byte-identical rewrites are not fan-out (documented in moduledoc).
  - Loading is not done here (the Server loads after recording the batch).

### Task P4: reload notices in the status line; rollback control

**Files:** `herdr_server/lib/herdr_server/reload_notices.ex` (bridge), `client/session.ex`, `client/state.ex`, `view.ex`, `herdr_server/lib/herdr_server/control.ex`, `live/bin/herdr-live`, tests.

- Bridge: subscribes to `HerdrReload.Notices` (retries if the registry is not running) and sends every attached session `{:notice, %{level, text, source: :reload}}`: `compile_error` (:error, first diagnostic file:line + message), `loaded` (:info, "reloaded N modules"), `rolled_back` (:warning, "rolled back batch K (M modules): reason summary"), `rejected` (:warning, "rejected: local fun from Mod at path"), `purge_blocked` (:warning).
- `Client.State.notice` holds the latest notice with an expiry (info 3s, warning 8s, error until the next loaded); `View.compute` renders it as a `%Scene.Node{role: :text, id: :notice, token: :error | :warning | :muted}` child of the `:status` node; protocol `{:notice, _}` is still forwarded to the client as today. Golden fixtures unchanged when no notice is present.
- Control: `HerdrServer.Control` listens on a unix socket (`{:local, path}`, path `$HERDR_LIVE_CONTROL` or `${XDG_STATE_HOME:-$HOME/.local/state}/herdr-live/control.sock`, dir 0700, socket removed on stop), line protocol: `rollback N\n` -> `ok <batch ids>\n` | `error <msg>\n`. Started only when `HerdrReload` is enabled. `live/bin/herdr-live rollback [n]` connects with a no-Mix `elixir -e` one-liner (`:gen_tcp.connect({:local, path}, 0, ...)`), prints the reply, exit 0/1. Ruling: stopgap until M12's API; local-only socket, no network listener.
- Local client restart: if `HerdrTerm.Application.start_local/1` can restart a crashed client with ≤ 30 lines and a test, do it; otherwise record for M7.
- Tests: each notice kind reaches a fake client's scene as the status child with the right token; expiry; control `rollback 1` rolls back and replies with the id; CLI script tested in a shell test against a running dev VM (or `mix run` harness).
- Commit `feat(live): show reload notices in the status line and add herdr-live rollback`.
