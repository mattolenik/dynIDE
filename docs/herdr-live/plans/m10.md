# M10 kitty graphics in composed frames: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** images a child draws with the kitty graphics protocol appear on the host in the right
place, clipped to pane rects, across splits, scrolling, resize, tab switches and Render reloads,
for in-VM and socket clients.

**Architecture:** ghostty (in the kernel) parses, stores and decodes images and computes placement
geometry (including unicode-placeholder virtual placements, already done by `crates/ghostty-vt`).
`Native.Vt.graphics_placements/1` returns scene-shaped placement maps; `Pane.Server` publishes them
in `Pane.Facts` on change; `View.compute` puts them in `Scene.Pane.graphics`. The terminal client's
pure `Render.Graphics` clips them to the pane, crops them around chrome and overlays, diffs them
against what the host has, and hands ops to `Native.Blit.frame`, whose output thread encodes kitty
APC commands after the cell diff inside the synchronized-output block. Image bytes reach the
client through an `images` MFA (in-VM) or `{:image, ...}` messages (socket, bounded).

**Tech Stack:** Elixir umbrella (`live/`), Rustler 0.38 NIFs (`herdr_kernel`, `herdr_term`),
vendored libghostty-vt through `crates/ghostty-vt`, Python harness for the scripted check.

**Spec:** `docs/herdr-live/milestones.md` (M10), the M10 brief (scope items 1-6 copied into the
tasks below), `docs/herdr-live/design.md` (scene contract, Native.Vt/Blit), the reference
pipeline in tag `herdr-reference` (`src/kitty_graphics.rs`, `src/kitty_graphics/surface.rs`,
`src/client/frame_output.rs`, `src/client/image_files.rs`, `src/platform/unix_image_files.rs`).

## Global Constraints

- No raw PTY/escape bytes enter the BEAM; image pixel data may (it is decoded storage, not stream).
- Kernel decides nothing about where things are drawn; `Native.Blit` writes what it is given.
- The placement pass is separate from `Render.Overlays` and runs after it; `Overlays.apply(row, [], ...)` stays a single clause.
- Every atom sent to a socket client exists in `herdr_scene` (architecture test).
- Contract changes in `herdr_scene` are additive, with validators and tests, published first (SPEC_PUBLISHED).
- New struct fields get defaults; GenServer callbacks already `Map.merge`; `code_change/3` where a process state shape changes.
- Guard (`HerdrReload.Guard`) around every call from a thin GenServer into editable code; no new blanket rescue.
- Rust: no `unwrap()` in production, `tracing`, no new crate dependency (base64 encoding: write a small encoder or reuse one already in the crate's deps).
- Frame bench at 15 panes must not regress more than 10% vs the M9 numbers in `results/m9.md`; `just live-bench-reload` targets must hold.
- Commit on `live/m10`, lowercase conventional messages, explicit paths, never push.

## Decisions (rulings, recorded in results/m10.md)

1. **Field name stays `graphics`** (design.md's `Scene.Pane.graphics: [placement]`, already a struct field); the brief's "graphics_placements" is the Native.Vt function name.
2. **Placements travel in the scene**, refreshed through `Pane.Facts` + `{:pane_facts, id}`; they may lag the rows by one session repaint window (16 ms).
3. **Host ids**: image `10_000 + :erlang.phash2({pane_id, image_id, fp}, 900_000)`, placement `1 + :erlang.phash2({pane_id, image_id, placement, piece}, 900_000)` (herdr's ranges; collisions not detected, as herdr).
4. **Replay every placement every frame that has any** (herdr: the host drops placements when cells under them are rewritten, and `ESC[2J` on repaint clears them).
5. **Media**: direct `t=d` base64 in 3072-byte chunks, `q=2`; file-backed `t=t` (client-written temp file the host deletes) for images over 32 KiB when the client's file transport is allowed: `TERM_PROGRAM=ghostty` and none of `SSH_CONNECTION SSH_TTY SSH_CLIENT TMUX STY HERDR_PANE_ID` set (herdr's gate). Files under `/tmp/herdr-live-kitty-<euid>/` (dir 0700, files 0600, `create_new`, names contain `tty-graphics-protocol`). A 1x1 probe goes first; until the probe file vanishes uploads go direct; a file not consumed in 10 s disables the transport (direct from then on). herdr's server-exported `t=f` with host responses is not ported (needs a response matcher on input; `t=t` covers the local large-image case).
6. **Occlusion**: a dimming modal (`chrome.dim`) hides every placement; other top-layer chrome (menus, toasts, non-dimming modals) and pane overlays (selection, search matches, copy cursor, link hover, scrollbar column) crop placements into pieces (rect subtraction, at most 32 extra pieces per frame, beyond that an occluded placement is hidden whole), as herdr's `Occlusion`.
7. **No offscreen retention**: an image no visible placement uses is deleted on the host and re-uploaded when it comes back (herdr keeps 16 / 64 MiB). `ponytail:` comment in the diff.
8. **Remote cap**: an image is forwarded over the socket when its data is at most 8 MiB (`config :herdr_server, :remote_image_max_bytes`); above it the client gets `data: nil` and draws a placeholder label `[image WxH]` in the placement's first visible row.
9. **Cleanup**: Render sends `:delete_all` (`a=d,d=A`) on its first frame after attach, on a guarded graphics-pass failure (and resets its cache), and the tty restore path (Rust, on exit or destructor) writes `a=d,d=A` before leaving the alt screen. Superseded (dropped) frames carry their graphics ops into the next frame.
10. **No host probe for graphics support** (herdr has none; config default on): `config :herdr_term, :kitty_graphics` (default true) or `HERDR_LIVE_KITTY_GRAPHICS=0` turns the pass off. Unknown cell pixel size = no placements.

## Contract (Task 1 publishes it)

Placement map in `Scene.Pane.graphics` (list sorted by `z`), validated by `HerdrScene.Scene.Graphic.validate/1`:

```elixir
%{image: {image_id :: pos_integer, fp :: non_neg_integer},
  placement: pos_integer,              # stable per (image, placement); virtual runs get the kernel's synthetic id
  x: integer, y: integer,              # pane-relative top-left cell in the viewport; negative = partly scrolled off
  cols: pos_integer, rows: pos_integer,
  x_off: non_neg_integer, y_off: non_neg_integer,   # sub-cell pixel offset
  src: {sx, sy, sw, sh},               # source rect in image px; sw/sh 0 = to the image edge
  px: {pw, ph},                        # rendered size in px, 0 = derive from cells
  z: integer,
  size: {w :: pos_integer, h :: pos_integer},
  format: :rgb | :rgba | :png,
  bytes: non_neg_integer}
```

Image payload (`HerdrScene.Scene.Graphic.validate_image/1`):
`%{format: :rgb | :rgba | :png, width: pos_integer, height: pos_integer, bytes: non_neg_integer, data: binary | nil}`.

Protocol additions (`HerdrScene.Protocol`):
- attach reply map may carry `images: {m, f, a}`; `apply(m, f, [pane_id, image_id | a])` returns an image payload or nil. `validate_attach_reply/1` accepts it (and its absence).
- server to client `{:image, pane_id, {image_id, fp}, payload}` (inline transports): `validate_server_msg/1` checks it.

## Review Focus

- A placement partly scrolled off the top (negative `y`) or wider than the pane: cropped, never drawn outside the content rect or over the border/sidebar.
- A child that clears the screen or deletes its image (`a=d`): the host placement and image go away on the next frame.
- Two panes showing the same image id: distinct host ids per pane, deleting one leaves the other.
- Tab switch away and back, and closing the pane: no ghost image left on the host.
- An image larger than the remote cap: placeholder label, no oversize frame, connection stays up.
