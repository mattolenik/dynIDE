# M18 Implementation Plan: release and distribution, plus the deferred perf and stability pass

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An installable, self-contained herdr-live release for macOS arm64 and Linux aarch64, a signed update channel that updates a running session in place through kernel-restart, local Homebrew/Nix packaging, dry-run signing, docs site and release notes; plus the M17 deferrals (kernel search, CLI envelope, `plugin update`, image carry, popup env removal) and the perf/stability pass.

**Architecture:** One Mix release `herdr_live` (`MIX_ENV=prod`, bundled ERTS, both NIFs in `priv/`) with the Rust broker and the existing `bin/herdr-live` launcher copied in. The launcher becomes layout-aware: in a release it runs the broker from `bin/`, the VM as `bin/herdr_live start`-equivalent, the CLI with the bundled `erl`, and the attach client with `bin/herdr_live eval`. Installs live in `<prefix>/lib/herdr-live/releases/<version>` with a `current` symlink; an update installs beside, flips `current`, and calls `kernel-restart`, whose target VM boots from the new `current`.

**Tech Stack:** Elixir 1.20.4 / OTP 29 Mix releases, Rust (broker, kernel), POSIX sh, Erlang `:crypto` (ed25519), `:httpc`, `:erl_tar`, Homebrew Ruby formula, Nix flake.

**Spec:** the M18 brief (`wave3-common.md` + `m18-brief.md`, quoted where load-bearing below), `docs/herdr-live/milestones.md` M18, `docs/herdr-live/design.md`, `AGENTS.md`.

## Rulings made by this plan (recorded in results/m18.md)

- R1. The release is `MIX_ENV=prod`: hot reload is off (`config :herdr_reload, enabled: config_env() == :dev` already). Live editing stays a source-checkout feature (`live/bin/herdr-live` in a clone). Cost: users of the release cannot edit it live; the gate's reload rows run on the dev build at the same commit.
- R2. One launcher script for both layouts (`live/bin/herdr-live`), detecting the release by `$root/releases/start_erl.data`. Cost: the dev launcher grows a branch per command path; no drift between two launchers.
- R3. Release distribution is `none` (`RELEASE_DISTRIBUTION=none`): no epmd, no node name; standby and primary never clash. Cost: no remote shell into a release VM.
- R4. Install layout `<prefix>/lib/herdr-live/releases/<version>/` + `<prefix>/lib/herdr-live/current -> releases/<version>` + `<prefix>/bin/herdr-live -> ../lib/herdr-live/current/bin/herdr-live`. The broker's VM argv goes through `current`, so a kernel-restart after an update boots the new version. The running broker binary itself is updated only by a full restart. Cost: broker-side fixes need a stop/start; broker link protocol must stay compatible across one update.
- R5. Update manifest: JSON, `schema: 1`, detached ed25519 signature over the exact manifest bytes (`<manifest>.sig`, base64). Trusted keys ship in the release (`releases/<v>/update-keys/*.pub`, raw 32-byte base64). The dev key pair is generated by script into `live/_build/release/keys/` (never committed). The human's real key replaces the dev public key at build time via `HERDR_LIVE_UPDATE_PUBKEY`.
- R6. The CLI envelope: herdr prints the whole API response; herdr-live adopts herdr's shape everywhere (pre-release, no external consumers to break), confirmed against `git show herdr-reference:src/cli.rs` and `src/cli/*.rs`. Task 10 records the exact shape and the final ruling.
- R7. `vendor/herdr-plugin-examples/` is removed from the tree; the plugins smoke fetches `ogulcancelik/herdr-plugin-examples` at pinned commit `18709cd` into `${XDG_CACHE_HOME:-~/.cache}/herdr-live/plugin-examples/18709cd`, and runs offline from that cache when present (SKIP with reason when neither network nor cache). The human may reverse this (status.md flags it).
- R8. D7-D9 (update notifications, release-notes display, announcements) are deferred: no published channel exists; `herdr-live update --check` is the seam. Cost: no in-app toast for new versions in the first release.

## Review Focus

- Install into a prefix path containing a space, and `herdr-live` reached through the `<prefix>/bin` symlink: every launcher path must quote and resolve symlinks (Task 2 test installs into `.../pre fix/`).
- Update with a tampered tarball (sha mismatch) or a manifest signed by an unknown key: refuse, leave `current` unchanged, exit 1 with a reason (Task 3 tests both).
- Update when no instance is running: install and flip `current`, skip kernel-restart, say so (Task 3 test).
- `kernel-restart` failure after `current` was flipped: the update flips `current` back and reports the abort; the old VM thawed (Task 3 test with a target that fails HELLO — broken `current` release).
- Release started from a different cwd than the install (e.g. `/`): pane shells start in `$HOME` / restored cwd, not inside the release dir (Task 1 smoke checks the first pane's `pwd`).
