# M1 Kernel (Vt and Pty) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A shell runs under a PTY, ghostty parses it on a kernel thread, and the BEAM reads packed rows and structured events. No raw stream bytes cross into the BEAM.

**Architecture:** The `herdr_kernel` crate keeps pure-Rust cores (`cell`, `vt`, `input`, `splitter`, `pty`) that cargo tests can exercise without a BEAM. Events go through an `EventSink` trait. A thin `nif` module wraps those cores in Rustler resources and adds a BEAM sink that monitors subscriber processes. Elixir facades `HerdrServer.Native.Vt` and `HerdrServer.Native.Pty` sit over the single NIF module `HerdrServer.Native`. `HerdrServer.Native.Keeper` owns the resources and the pane-id table, which other processes read from ETS.

**Tech Stack:** Rust (root `rust-toolchain.toml`), Rustler `=0.38.0` crate and `~> 0.38.0` Hex, `crates/ghostty-vt` (vendored libghostty-vt, Zig 0.16.0), `portable-pty` (vendored patch), `libc`, `serde_json` (dev-dependency only), OTP 29, Elixir 1.20.4.

**Spec:** `docs/herdr-live/milestones.md` (M1), `docs/herdr-live/design.md` (The split; NIF interfaces: herdr_kernel Native.Vt and Native.Pty; Rendering pipeline; What hot reload does not cover), `docs/herdr-live/packed-cells.md`, `AGENTS.md`.

## Event and term shapes (binding, all tasks)

```
{:damage, id, gen}            id :: non_neg_integer (Keeper pane id), gen :: non_neg_integer
{:exit, id, status}           status :: non_neg_integer | {:signal, signo} | {:panic, binary}
{:osc, id, code, payload}     code :: non_neg_integer (never 0, 1, 2, 7); payload :: binary | {:truncated, binary}
{:dcs, id, payload}           payload :: binary | {:truncated, binary}   (the bytes between ESC P and ST)
{:bell, id}
{:title, id, binary}          OSC 0 and OSC 2
{:pwd, id, binary}            OSC 7 raw payload (e.g. "file://host/tmp")
```

Rows: `{gen, [{row_index, packed_row_binary}]}`, viewport rows `0..rows-1`, binaries per `docs/herdr-live/packed-cells.md`.

## Review Focus

- The child exits before anyone subscribes. The exit status must still reach the first subscriber, because the sink retains it (Task 6, `exit before subscribe` test).
- A burst of output then silence. The last chunk's damage must arrive without more input (quiescence flush), and the final `dirty_rows` must match the final screen (Task 5, `burst_then_silence_flushes`).
- The reader panics while holding the core lock. Later BEAM calls on that vt must return normally (poison recovered) and the VM stays up (Task 5 `panic_in_reader_reports_exit_once`, Task 6 ExUnit panic test calls `Vt.full_rows` afterwards).
- A background job holds the slave open after the shell exits (`sh -c 'sleep 30 & exit 3'`). The exit event fires on reap with status 3, not on EOF (Task 5, `exit_on_reap_not_eof`).
- Writes to an exited pane return `{:error, :closed}`. A write flood to a child that is not reading returns `{:error, :backpressure}` with bounded memory (Task 5 `write_after_exit_is_closed`, `backpressure_when_child_not_reading`).

### Task 4: OSC/DCS splitter

**Files:**
- Create: `live/native/herdr_kernel/src/splitter.rs`
- Modify: `lib.rs`

**Interfaces:**
- Produces:
  - `pub struct Splitter`
  - `pub enum Seq { Osc { code: u32, payload: Vec<u8>, truncated: bool }, Dcs { payload: Vec<u8>, truncated: bool } }`
  - `impl Splitter { pub fn new() -> Self; pub fn observe(&mut self, bytes: &[u8], out: &mut Vec<Seq>) }`
- It observes only and never removes bytes (the same bytes still go to ghostty). It is stateful across chunk boundaries. OSC is `ESC ]` and DCS is `ESC P`. Both terminate on `BEL` (OSC only) or `ESC \`, and are aborted by `CAN`/`SUB` or a new `ESC` that is not `\`. 7-bit introducers only: C1 `0x9d`/`0x90` are UTF-8 continuation bytes and are ignored. The code is the leading decimal digits before `;` or the end. OSC without a numeric code is dropped. The payload is the bytes after `code;`. Caps are 1 MiB for code 52 and 4096 bytes otherwise; past the cap, keep the prefix, set `truncated`, and discard the rest until the terminator. Use herdr's `OscStreamCollector` in `src/pane/osc.rs` as the reference state machine.

    - `pub fn spawn(vt: Arc<Vt>, opts: SpawnOptions, sink: Arc<dyn EventSink>) -> io::Result<Arc<Pty>>`
    - `pub fn id(&self) -> u64` and `pub fn os_pid(&self) -> u32`
    - `pub fn write(&self, bytes: &[u8]) -> Result<(), WriteError>`
    - `pub fn resize(&self, cols: u16, rows: u16, px: Option<(u16, u16)>) -> io::Result<()>`, PTY winsize only
    - `pub fn kill(&self, signo: i32) -> io::Result<()>`: `libc::kill(pid, signo)`, with ESRCH treated as Ok
    - `pub fn set_hidden(&self, hidden: bool)`: on `false`, `mark_all_dirty` + `refresh` + `Damage`
    - `pub fn request_full_damage(&self)`: `reset_read_cursor`, then send `Damage(current gen)`
    - `pub fn exit_status(&self) -> Option<ExitStatus>`
    - `#[cfg(any(test, feature = "test-nifs"))] pub fn inject_reader_panic(&self)`: the reader panics before processing its next chunk, including on its next wake
- Spawning: `portable-pty` `native_pty_system().openpty` and `slave.spawn_command`. Env entries are added to the inherited environment, and `TERM` defaults to `xterm-256color` when the caller does not pass it. Drop the slave after spawn. Confirm the vendored crate resets signal dispositions and mask and closes stray fds in the child (`vendor/portable-pty/src/unix.rs` ~L228-280), and note this in a comment.
- Reader thread loop:
  - Block in `poll(master_fd, wake_pipe)` with no timeout.
  - Read up to 16 KiB non-blocking and feed `Splitter.observe`, then `vt.write`.
  - Map `WriteEffects` and `Seq` to events. Code 0/2 becomes `Title`, 7 becomes `Pwd`, 1 is dropped, other codes become `Osc`, and DCS becomes `Dcs`. Send one `Bell` per bell count, capped at one per chunk. Clipboard writes from ghostty are ignored, since OSC 52 arrives via the splitter.
  - Hidden: skip refresh and damage.
  - Visible: if `poll(master_fd, 0)` reports no more data (quiescent), or 4 ms or more have passed since the last emitted damage, call `refresh` and send `Damage(gen)`. Otherwise stay pending.
  - EOF or EIO ends reading.
- Waiter thread: `libc::waitpid(pid, &mut status, 0)` on that pid only (never `-1` and never `WNOHANG` spinning), so erts' own child handling is untouched. On reap it records the status and wakes the reader through the pipe.
- The reader then drains the remaining readable bytes (non-blocking until EAGAIN, EOF, or 64 KiB), does a final refresh and damage, and sends `Exit` exactly once (`AtomicBool`).
- Writer thread: `Mutex<VecDeque<Vec<u8>>>` + `Condvar`, writing to the master fd in order. BEAM writes check the 1 MiB cap (accepted whenever the queue is empty). ghostty `WritePtyCallback` replies push without a cap through the same queue.
- `write` after exit, or after the writer hit EPIPE/EIO, returns `Closed`.
- Every thread runs under `catch_unwind`. On a reader panic: send `Exit(Panic(msg))` once, `kill(SIGKILL)` the child, and stop. The waiter still reaps, but it does not send a second exit.
- When the last `Arc<Pty>` drops, SIGHUP the child if it is still alive.

- `subscribe` monitors the pid (it is a no-op if already present), calls `pty.request_full_damage()` (which sends `{:damage, id, gen}`), and immediately sends `{:exit, id, status}` if the child already exited.
