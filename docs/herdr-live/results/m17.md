`preloaded ... in X ms` log line now reads 0 ms; the cost of the preload is inside `vm up`.

## Bugs found and fixed on the way

- **Pre-M17 production bug: the first `View.compute` could miss its 50 ms guard budget.**
  Interactive-mode lazy module loading made the first compute after boot load dozens of
  modules inside the budget; the guard timed out, and a scene push never retries, so a first
  client could sit with no scene until the app changed. Found while chasing the server_test
  flake "Store restart adopts a mapped pane". `Application.start` now calls
  `Handoff.Link.preload()` (`ae311d86`). Same commit: server_test slept 50 ms for a 20 ms
  debounced mirror write; 8 sleeps became a `mirrored/0` poll. 20/20 server_test runs after.
- A reload of `Config` kept `ui.sound` paths that were removed from the file (Task 24 fix).
- A git poll could stack hung `git` processes per tick and take `index.lock` (Task 12 fix:
  in-flight set, `--no-optional-locks`, `spawn_monitor`).
- A popup pane was not carried across a handoff: stuck input and a leaked pane (Task 23
  fix `d9fa8762`).
- An improper-list drop target crashed the client session (Task 16 fix).
- Found by the gate: the coalesced `api_connect` line (A6) dropped the connects of the
  last minute, so a short run summarised as 1 connect and the `agent` tty harness check
  (`connects >= 5`) failed. The listener now logs the pending count when it stops
  (`a415d259`, listener_test).
