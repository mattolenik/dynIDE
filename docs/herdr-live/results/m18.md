## Concerns

- Hardened-runtime launch of the signed BEAM (JIT, NIF dlopen, `erl_child_setup`) is
  untested until a real signed run. `signing.md` step 4 smokes the signed tree before
  notarizing.
- Nix is untested (no nix on the host). Possible first-run failures: autoPatchelf missing a
  library, strip settings, macOS.
- x86_64 Linux is not built. Linux has only run in an aarch64 VM, never on bare metal.
- Reload latency for state-shape edits grew since M7. It is real growth (it reproduces on
  Linux at low load) and is still inside targets.
- Images: a graceful handoff of image-heavy panes grows the final blob by up to ~21 MiB
  per pane inside the frozen window. That case is unmeasured, and the over-cap branch is
  untested end to end.
- The reload watcher flake's cause is inferred, not reproduced.
- A Linux standby could lose the restart race before Task 3's argv fix. That is now fixed
  at its root; covered by `update_check.sh` on both OSes.

## Hazards for live users

- M18 changed NIFs: `vt_search`, env removal on spawn (`pty_spawn` decodes `{name, nil}`),
  `vt_graphics_replay`, and the Linux foreground-job probe. A running instance needs
  `kernel-restart` to get them.
- Hot-reloading the new `app/store.ex` or `native/keeper.ex` before that `kernel-restart`
  makes every pane spawn fail with `badarg` (the old NIF cannot decode nil env values) until
  the restart. A merge into a running checkout triggers that reload. Stop the instance
  first, or run `kernel-restart` right after the merge. Copy-mode search on the old kernel
  says "copy mode search failed" and the session stays up. Recorded in
  [editing-live.md](../editing-live.md).
- The broker changed (`71def1b9`: `kernel-restart` takes a target argv). The dev launcher
  sends the old empty body, which an old broker understands. A release needs the new
  broker, which only a full stop and start brings.
