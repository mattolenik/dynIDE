## Rulings

Each ruling gives the decision, why, and what it costs if wrong.

1. **Rustler 0.38.0 on both sides.** Hex `{:rustler, "~> 0.38.0", runtime: false}`, crate `rustler = "=0.38.0"`.
   - Why: Hex's latest is 0.38.0. crates.io has 0.39.0, but the Mix loader and the crate are released in lockstep. The default config compiles the crate from source during `mix compile` (no precompiled NIFs). Note that Rustler compiles in release mode under dev too.
   - Cost if wrong: one version bump in two places.
2. **Each NIF crate is its own Cargo workspace (empty `[workspace]`), not a root workspace member.**
   - Why: this keeps herdr's root build, lockfile and profiles untouched. Each crate owns `panic = "unwind"` (profiles are only honoured at a workspace root), and Rustler builds each crate in its own `target/`.
   - Consequence: the root `[patch.crates-io] portable-pty` is not inherited. M1 must add `portable-pty = { path = "../../../vendor/portable-pty" }` under `[patch.crates-io]` in `herdr_kernel`. Comments in the Cargo.toml and AGENTS.md say so.
   - Cost if wrong: if the crates later want shared deps or a single lockfile, they can move into a `live/native` workspace with mechanical edits.
3. **Justfile placement is `live/live.just`, pulled in with `import 'live/live.just'` from the root justfile.**
   - Why: recipes keep their requested names (`live-test`, ...). Paths use `source_directory()`, so they work from any cwd. Fork additions stay out of herdr's 268-line justfile, which keeps upstream merges clean.
   - Cost if wrong: a cut-and-paste into the root justfile.
4. **The launcher is dev-only.**
   - Why: `live/bin/herdr-live` resolves `live/` from its own path, following symlinks, and runs `mix run --no-halt` with `MIX_ENV` (default `dev`). No release config exists yet, so release lookup waits for M18.
   - Cost if wrong: about five lines of shell when releases exist.
5. **The log sink is stdio redirection, not a Logger file handler.**
   - Why: the launcher sends stdin from `/dev/null` and stdout/stderr to `$HERDR_LIVE_LOG`, which defaults to `${XDG_STATE_HOME:-$HOME/.local/state}/herdr-live/herdr-live.log`. That catches Logger, compile output and anything that reaches fd 1/2. The terminal client opens `/dev/tty` itself, so it does not need the inherited fds.
   - Cost if wrong: if a file handler with rotation is wanted, it is a few lines in `config/runtime.exs`.
6. **`consolidate_protocols: Mix.env() == :prod` in every app, so it is false in test as well as dev.**
   - Why: M4's reload tests run under `:test`. The dependency-rule test enforces it.
   - Cost if wrong: slightly slower protocol dispatch in tests.
7. **Module namespaces are app-prefixed.**
   - Why: `HerdrScene.*`, `HerdrServer.*` and `HerdrTerm.*`, so design `Native.Vt` becomes `HerdrServer.Native.Vt`. This follows Elixir convention and avoids collisions in the shared VM namespace.
   - Cost if wrong: a mechanical rename.
8. **There is one NIF module per crate: `HerdrServer.Native` and `HerdrTerm.Native`.**
   - Why: Rustler binds one Elixir module per crate. The design's `Native.Vt`, `Native.Pty`, `Native.Tty` and `Native.Blit` are Elixir facades over it.
   - Cost if wrong: if M1 prefers several NIF libraries, each is a new crate.
9. **CI matrix runs on `ubuntu-latest` and `macos-latest`.**
   - Linux: setup-beam is pinned to v1.24.1 with loose matching (OTP "29", Elixir "1.20.4"), because strict mode needs exact patch versions that drift.
   - macOS: Homebrew Erlang/Elixir, because setup-beam does not support macOS. An Elixir floor gate (1.x with minor >= 20) guards it.
   - Shared: Rust 1.96.1, Zig 0.16.0 cached as in `ci.yml`, and just.
   - Cache key: OS, the BEAM toolchain id and `mix.lock`. It covers `live/deps`, `live/_build` (including the dialyzer core PLT, via `plt_core_path`) and `live/native/*/target`. Concurrency is cancel-in-progress.
   - The workflow has never run, because this branch is never pushed. actionlint is clean.
   - Cost if wrong: first-run CI fixes.
10. **The dependency-rule test discovers `apps/*`.**
    - Why: discovery means a future `herdr_gui` is checked without editing the test. For the running app it reads `Mix.Project.config()`, because Mix refuses `in_project` on the already-defined project. It runs `async: false` because `in_project` changes the VM's cwd.
    - Cost if wrong: none; the data is equivalent.
11. **Rustler's output in `apps/*/priv/native/` is gitignored.**
    - Why: it is a build artefact.
    - Cost if wrong: none.
12. **`results/` gets no `.gitkeep`.**
    - Why: this file makes the directory exist.
    - Cost if wrong: one empty file.
13. **The plan lives at `docs/herdr-live/plans/m0.md`.**
    - Why: the root `.gitignore` ignores `/docs/*` except `docs/herdr-live/`.
    - Cost if wrong: moving one file.
14. **AGENTS.md is accepted at 166 lines, against a target of about 150.**
    - Why: every remaining line carries a required rule.
    - Cost if wrong: a trim pass.
15. **Process: Tasks 2 and 3 (the two NIF crates) shared one implementer and one review.** In addition, one single-line CI fix was re-reviewed by me, not a subagent. The final review covered both.

## Known gaps and notes for M1-M4 owners

These come from the final review.

- **M2/M3: the launcher smoke will conflict with `Tty.Owner`.**
  - The smoke asserts an empty transcript and an unchanged tty. Once `herdr_term` starts `Tty.Owner` under `mix run`, it will put `/dev/tty` into raw mode, and both assertions fail by design.
  - The owner needs a headless switch (for example, an env var that stops the terminal client attaching) or a split smoke.
- **M3: no app can host cross-app integration tests.**
  - The dependency rule forbids any app depending on both `herdr_server` and `herdr_term`.
  - Before M3, decide whether a test-only integration app is allowed, or whether such tests boot both apps from the umbrella.
- **M3: compiling `herdr_server` always builds the kernel crate (Zig + cargo).**
  - This happens even when working against the fake kernel. Rustler's `skip_compilation?` is available if it hurts.
- **M4: `Reload.Compiler` calling Mix from lib code** will need `plt_add_apps: [:mix]` for dialyzer.
- **Signals during first-boot compile:** SIGTERM is not exercised then. It is only tested after `herdr-live started`. A cargo/zig child spawned by Rustler might outlive an interrupted first compile.
- **Native crates are compiled twice.** Rustler builds release mode into `target/release`, while `cargo clippy`/`cargo test` build debug, so the first clean `live-check` builds them twice.
- **Dialyzer noise:** it prints `No :ignore_warnings opt specified`. This is informational, and silencing it needs an ignore file.
- **Adding a NIF:**
  1. Add a `#[rustler::nif]` fn in the crate; `rustler::init!` auto-registers it.
  2. Add `def name(...), do: :erlang.nif_error(:nif_not_loaded)` in `HerdrServer.Native` / `HerdrTerm.Native`.
  3. Add a facade in the matching `Native.*` module.
- **Adding an app:** from `live/`, run `mix new apps/<name>`. Depend on exactly `{:herdr_scene, in_umbrella: true}` and set `consolidate_protocols: Mix.env() == :prod`. The dependency test enforces both.
