## Threat model

Scope: a socket reachable by other local users, a token that must not travel, and a client that decodes server terms.

- Directory and socket: `client.sock` and `client.token` live in the API socket's dir (`Wire.paths/1`). The directory is 0700 and the socket 0600. Another uid cannot connect.
- Token: 32 random bytes, hex, 0600, created once and kept across VMs. The first frame on every connection is `{:auth, token}` and the comparison is constant time. A wrong or missing token gets `{:refused, "bad token"}` and a close. The token file never leaves the server host: `attach <host>` runs `herdr-live attach-relay` on that host over ssh, the relay reads the file there and sends `{:auth, token}` to the socket; the client machine only sees the relay's stdio. Local attach reads the file itself. An empty or whitespace-only file counts as missing (replaced atomically, bounded retry), and an empty server token authenticates no one (`5a13f76e`).
- ETF decoding with `[:safe]` both ways: the server decodes client frames with `binary_to_term(.., [:safe])`, rejects anything that is not plain data (`Persist.Schema.plain?/1`: no pids, refs, funs, ports), then validates against `Wire`. An invalid frame gets a warning notice and the connection stays. The client decodes server frames with `[:safe]` after preloading every module of `herdr_scene`, `herdr_reload` and `herdr_term`, so only atoms already known to the client exist; an unknown atom is dropped with a client-local notice and a reconnect after the longest backoff.
- Frame limits: `{:packet, :raw}` with `<<len::32, etf>>` parsed in Elixir. Client to server at most 32 MiB (pastes up to 16 MiB), server to client at most 64 MiB. An oversize or unframeable stream closes only that connection. Before auth the server reads at most 64 KiB,. A client that reads nothing for `stuck_ms` (30 s) is dropped; a wedged server cannot block the relay past its 30 s send timeout.
- `client_id` bounds: 1 to 64 bytes of `[0-9A-Za-z_-]` (`3b12b615`). The id is part of the broker key `client/<id>` and `Native.Link.frame_key/2` carries a u16 length; it now raises over 65535 bytes instead of wrapping. A resume under the same id for another target is refused.
- No command execution from the wire: the sound command is never taken from a socket scene (ruling below). Terminal escapes and glyphs come from packed rows that the client rasterizes; the server sends no ANSI.
- SSH authentication: `BatchMode=yes` always (R13), so attach needs a key or an agent; there is no password prompt. Host-key policy is the user's ssh config. `ServerAliveInterval=10`, `ServerAliveCountMax=3`.
- Never epmd, never Erlang distribution on the wire; the transport is one unix socket and ssh stdio.
- Out of scope: an attacker with the server's uid (reads the token, owns the VM anyway); a hostile server against the client (the client trusts what the server draws, bounded by `[:safe]`, the frame cap and the atom set, but a malicious server can still show any content, set the clipboard, open URLs and ring alerts through the normal scene vocabulary); a hostile ssh host; traffic analysis.

## Bugs found and fixed on the way

- **Atom leaks that broke `[:safe]` decode on the client**, found by the smoke and the architecture test: status node props carried server atoms and arbitrary module lists (`05392787`); `{:handoff, %{phase: :adopted}}` had no atom on the client, so the carried socket was dropped and B reconnected (`128a479b`); `{:detached, reason}` atoms (`4cda49bd`, `Protocol.detach_reasons/0`); 23 M13 chrome id atoms (`1eecf856`, `Chrome.ids/0`). The undecodable frame also looped reconnects at the shortest delay; it now waits the longest backoff (`bb94ef98`).
- **THAW deadlock**: restarting `Client.Socket` called `Link.take_adopted` into a blocked `Link`. Adopted entries are claimed at app start, not in `Socket.init` (`77eedff3`).
- **fdopen fd leak**: `:gen_tcp.fdopen` sockets are prebound, so `gen_tcp.close` never closes the fd; adopted conns never EOF'd their client and leaked. New NIFs `fd_raw/1` and `fd_close/1`; the hold dup is closed right after `hold/3` and dropped before any server close.
- **Ack restarts the frame window**: an empty flush before each ack delayed every echo by about 8 ms (idle typing p50 9.29 to 0.44 ms) (`08df5f4c`).
- **Onboarding in the bench**: M13's first-run modal in the bench broker swallowed keys, so "key not echoed". The driver now writes a config with `onboarding = false` (`1c5b8bd4`).
- **Umbrella supervisor restart budget**: the integration test killed `App.Store` and spent the shared `HerdrServer.Supervisor` budget (3 per 5 s), shutting the app down for later tests. It now uses `terminate_child`/`restart_child` (`a2c45273`). The limit stays (it is a rollback trigger).
- **Empty token loop**: an existing empty `client.token` made `Socket.init` recurse forever, and a whitespace-only file authenticated an empty token (`5a13f76e`).
- **client_id wrap**: an unbounded id overflowed the u16 key length in broker frames (`3b12b615`).
- Also: crash/abort adopting a stale blob mid-frame, a crashed conn keeping its hold, relay backpressure and stdout tail loss, `session.snapshot` crashing with no focus (`73c1cf93`), a resume under another target (`36e81ed8`), a fresh session replaying input typed while away (`6c5bb6bb`), refusals and boot failures invisible behind `exec` (`6c5bb6bb`), a broken outbox never reset after a guarded failure and the launcher not forwarding signals to the client VM (`d76a6be3`), and the relay's epipe exit.

## Known gaps and concerns

- **Observe of a hidden-tab pane is stale** until its tab is shown (ruling 8).
- **Typing under flood p50 is about 11 ms** (11.5 macOS, 13-15 Linux) because other panes' rows fill the 8 ms frame window. Idle typing is 0.45 ms.
- **`Mirror` presentation state is lost across handoff**; only the connection, `acked` and the unparsed buffer are carried, and the client sees a full scene.
- **One keystroke can apply twice after a crash** (at-least-once): after a crash the client resends what it has not seen acked, and the new session cannot know which of those the dead one already applied (the crash path starts a fresh or resumed session, not a carried one).
- **The relay resolves server paths in ssh's non-interactive env.** A server with a custom `HERDR_LIVE_API`, `HERDR_LIVE_CLIENT_SOCK` or `XDG_STATE_HOME`, or `herdr-live` off the non-interactive PATH, is not found; set `HERDR_LIVE_REMOTE_BIN` to a wrapper that exports them (documented in the `bin/herdr-live` header).
- **Other owners' tests with `/tmp` `unique_integer` sockets** can collide across parallel VMs (`:eaddrinuse`): `native/link_test`, `link_fd_test`, `snapshotter_test`, `store_adopt_test`, and api tests with their own dirs.
