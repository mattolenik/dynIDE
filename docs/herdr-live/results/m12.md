## Exit criteria

**API conformance tests.**
- `test/api/conformance_test.exs` generates one test per (method, declared error code): 84 cases. Each case produces that code over a real socket, and a declared code with no producing case fails the suite.
- Every error assertion in the other API tests (conn, listener, topology, pane_io, events) checks that the code is among that method's declared errors (plus the implicit `internal`).
- Success results and event lines are validated against the Spec, and undeclared fields fail.
- `spec_test` "api.md is generated from the spec" checks the schema file against the implementation.
- Counts at 620c3b24: herdr_server 415 tests (about 110 of them under `test/api`), herdr_cli 39, herdr_integration 17 (with the CLI conformance test that every Spec method is reachable from argv with valid params) plus 6 real-kernel tests (one reads pane text through the API from a real pty).

**CLI used by an agent in the self-hosting loop.** `tty_harness.py agent` launches `bin/herdr-live` attached in a 120x40 pty. In the first pane's shell it types `$HERDR_LIVE_BIN` commands: split a pane, run `echo` in it, wait for the output, read it, list panes, ask for agent state, and time 10 pings. The PASS lines from the Linux gate run at 620c3b24 are below; macOS gives the same lines, with a mean of 155-198 ms depending on load.

## CLI startup latency

`bin/herdr-live ping` against a running headless instance:

| option | p50 | p95 | load |
|---|---|---|---|
| (a) `elixir -pa <ebin> -e 'HerdrCli.main(System.argv())'` | 273 ms | 323 ms | 50-66 |
| (b) escript (`mix escript.build`, not shipped) | 262 ms | 359 ms | 50-66 |
| (c) `erl -noinput -boot no_dot_erlang -pa .. -run Elixir.HerdrCli main_erl` | 153 ms | 205 ms | 50-66 |
| (c) through `bin/herdr-live` (shipped) | 168 ms | 200 ms | 50-66 |
| shipped, final commit, 20 runs, `ping` | 279 ms | 318 ms | 17.6 |
| shipped, final commit, 20 runs, `pane list` | 282 ms | 464 ms | 17.6 |
| from a pane in the agent smoke, mean of 10 `ping` | 153-183 ms (Linux), 155-198 ms (macOS) | | 3.7 (Linux) / 16-24 (macOS) |

(a)-(c) were measured interleaved in one session, so they compare fairly. The two rows at load 17.6 are a later single-session run with Python timing included. Bare `erl -noinput -eval 'halt().'` took 130-150 ms in that same minute, and `erl -run` of the CLI took 150 ms, so the VM boot is the floor. The sh launcher's three forks added about 80 ms under that load. The load never fell below 12 during the session. The run after the M8 rebase at load 45-50 gave a p50 of 2.5 s; it is discarded as a load artefact.

I chose `erl -noinput -run` over an escript and over `elixir -e`. It is about 110 ms faster per call than either and needs no build step at call time. The elixir ebin dir is found by asking `elixir` once and caching the answer in `_build/dev/herdr_cli.elixir_ebin`, because version-manager shims defeat symlink resolution. VM flags (`+S 1 +A 0`, `start_clean`) gave nothing. Inside the BEAM the call itself costs a few ms; the rest is VM boot.

## Rulings

Rulings 1-12 were accepted by the coordinator.

1. There was no SPEC_PUBLISHED: the API spec lives in `HerdrServer.Api.Spec`, so herdr_scene is unchanged. Cost if wrong: a remote or GUI client needs the spec moved into herdr_scene.
2. `reload.rollback`'s `n` is optional, default 1, like the old `rollback [n]`. Cost: none.
3. `tab.create` with `focus: true` also makes its workspace active. Cost: none.
4. Per-pane facts in `Api.View` sit behind one function, to be rewired to M9's `HerdrServer.Pane.Facts` when it lands. Cost: one function.
5. `App.Commands` keeps its id-targeted functions until M13's workspace Actions land; then it delegates. Cost: a rewire task.
6. M13's `{:alert, %{kind: :notification}}` becomes an API event `notification.shown` once the alert path lands. Cost: a later commit.
7. The CLI task ran in parallel with the pane I/O and events tasks, on disjoint files. Cost: none occurred.
8. A rollback that could run twice (an exit reaching the Guard's re-run) was promoted to Important and fixed. Cost: none.
9. The CLI connect retry is 2 s even when the socket file is missing, because the handoff gap removes the file. Cost: "not running" takes about 2 s.
10. Promoted to fixes: CLI crash reports on stdout, `herdr-live ""` launching an instance, and an untimed wait polling after its client left. Cost: none.
11. The deferred minors were triaged as the final review advised. The rest are accepted under Known gaps.
12. Parked: a stream or wait open across the reload from pre-fix code dies once (that code never left this branch). Also parked: the hub can keep a stale `last` after unsubscribing (memory only; a test assertion could flake).
13. The Linux reset was a defect found by verification, so it got one targeted fix and a scoped re-review outside the single final fix wave. Cost: none.
14. `failed` is not declared for `pane.wait_for_output`. After the polling rework, a client close ends the wait with no answer, so nothing can return `failed`. Cost: none.

## Known gaps

- `tty_harness.py demo` flakes under load (pre-existing, M7).
- Workspace and tab ids are reused after a close (highest + 1); pane ids are never reused. This is documented in api.md. Monotonic ids need a Session field that M13 owns.
- `App.Commands` duplicates the close and drop-tab logic of `App.Actions`, to keep the shared-file edit small.
- `pane.read` has no `recent-unwrapped`, `detection` or ANSI source. `pane.process_info` has no foreground process list. `pane split` has no `--cwd`/`--env`.
- Events for changes made while the Store restarts are lost; the hub resumes from a fresh snapshot. The first subscription has a tiny subscribe-then-snapshot window that can emit inverted events.
- A running wait buffers at most 16 pipelined request lines. Past that, a client close is seen only when the wait ends.
- Each connection has a 1 MiB receive buffer (`:line` packets are cut at the buffer, not refused). Idle connections wake once a second, so they follow reloads.
- The api telemetry writes one `api_connect` line per CLI call.
- The agent smoke times pings with `date +%s%N`, which needs GNU or recent macOS `date`.
- The CLI caches the elixir ebin path and does not notice an Elixir upgrade while the old version's dir still exists.

## Notes for other milestones

- **M13**:
  - When your workspace Actions land, `App.Commands` should delegate to them.
  - Monotonic workspace and tab ids would end id reuse.
  - The `{:alert, ...}` notification path can become an API event.
  - `App.Ui` stays out of the API.
- **M14**: plugins can drive herdr-live through `HERDR_LIVE_BIN` and `HERDR_LIVE_API`, which every pane shell inherits.
- **M16**: `session.snapshot`, remote attach and terminal streams are deferred to you. The JSON API is local-only today, protected by the 0700 dir.
- **M8**: the API persists nothing.
