## Test-on-save default: off

Measured on the real umbrella (`live/bench/reload/test_gate_bench.exs`), gate on, five
saves of `view.ex` (which has `test/view_test.exs`). Per iteration, save to
`{:tests, :passed}` / save to `{:loaded}`: 872/1007, 884/1015, 853/972, 861/981,
855/980 ms. Median **861 ms to tests passed, 981 ms to loaded**. The ungated
`View.compute` edit is 186-196 ms save to visible (M6 gate). The gate makes every save
about 5x slower and puts a View edit right at the 1 s design target. A larger test file
(herdr_server's 220 tests) costs seconds. So the default is off and the gate is a switch.
Turn it on when an agent edits code with good tests and you prefer a blocked load to a
rollback.

## Telemetry and the exit criterion

Every crash and reload event is one greppable line: `grep 'herdr-event ' "$HERDR_LIVE_LOG"`.
`live/scripts/log_summary.py [LOG] [--since ISO] [--json]` prints, in order: period, VM
starts, reloads, modules reloaded, max fan-out, compile errors, rollbacks (manual and
auto, with reasons), guard failures (attributed or not), tests (passed, failed, stale),
syncs, handoffs (crash, graceful, failed, with p50/p95/max ms), crashes per process, store
restarts, session losses, unparsed lines, and `exit_criterion: session_losses=0 -> OK`
(or `FAIL (N)`).

**Session losses** are `session_lost` lines plus unclean broker restarts. `session_lost`
lines come from the broker's fallback restore (children not carried) and from the Store
closing or orphaning live panes: fresh restart, failed reconcile, unusable carry. An
unclean broker restart is a `broker_start` after a `broker_start` with no `broker_stop`
between them. A Store restart from the ETS mirror keeps the layout, so it is counted as
`store_restarts`, not as a loss. The week passes when `session_losses=0`. Each loss line
carries `proc` and `reason`, so it can be attributed, or not, to a brain edit.

## Rulings

Each gives the decision, then what it costs if wrong.

1. **Detach and quit are the same until M16.** The local client's exit stops the VM.
   Cost: a detach-without-quit feature request.
2. **Test-on-save runs `mix test` in a separate OS process before the compile.** In-VM
   ExUnit would run against half-loaded code, because Mix deletes old code during a
   compile. Cost: about 0.7-0.8 s per gated save.
3. **Gating is serialized in `HerdrReload.TestGate`.** A blocked-path set is re-tested on
   every later gated batch, and the reload is skipped if any source changed during a run.
   Reason: Mix compiles all stale sources, so a single-path gate would be bypassed. Cost:
   one more process; a gated save waits behind earlier gates.
4. **The test-gate bypass via standby compile or handoff is documented, not fixed.** A new
   VM's `mix run` compiles a blocked source, and the blocked set does not survive a
   handoff. The gate is off by default. Cost: a blocked source can load after a crash.
5. **In `:gate` mode a batch with no mapped tests broadcasts `{:tests, :none}`, which
   clears the tests node.** This supersedes the pre-flight ruling. Cost: one extra
   repaint.
6. **Two scenes per reload event per client** (notice, then status). Reload happens at
   human rate. Cost: one extra `View.compute` per client per reload.
7. **The `View.compute` cost of +2.3 µs per call is accepted** (above).
8. **The local client restarts on `:shutdown` too**, unless a deliberate-stop marker is
   set (detach, quit, handoff `:begin`), because supervisor intensity exhaustion exits
   `:shutdown`. A start failure counts against the limit, except `{:tty_open, _}` (no host
   terminal), which is not retried. Cost: an unexpected `:shutdown` source restarts the
   client once.
9. **Session `:shutdown` exits are not logged as crashes.** Orphan tracking still applies.
   Cost: a crash shaped like a shutdown goes unlogged.
10. **store.ex stays at about 505 lines, not 380.** The `restore/2` orchestration stays in
    Store. Moving more would need `%Store{}` in the helpers. Cost: a later split of
    effect/io.
11. **The selfhost clean-tree check compares against a start-of-run snapshot**, because
    `live-check` runs before committing, on a dirty tree. Cost: an extra edit to an
    already-dirty file goes unnoticed.
12. **The tty harness skips its launcher modes inside a herdr-live pane.** The full
    `live-check` runs outside the dogfood instance, because those modes compile into, and
    reload, the instance's own `_build`. Cost: harness coverage only when run outside.
13. **Session losses = `session_lost` + unclean broker restarts; `store_restarts` are not
    losses.** Cost: a broker restart that kept its children would be miscounted (none is
    possible today).
14. **A first reload before the status bridge subscribes is seeded from the newest batch.**
    A rolled-back seed shows the reason `earlier`, because a batch records no reason.
    Cost: one extra call into `HerdrReload.Server` on subscribe.
15. **The ledger and briefs live under `.superpowers/sdd/m7` and are not committed**, as
    in M6. Cost: they are lost on `git clean`.
16. **The in-pane `mix test` halt got one targeted residual fix after the final fix
    wave**, because agents test from inside herdr-live during the dogfooding week. Cost:
    one extra review round.
17. **Task 5 ran in parallel with the Task 4 review, Tasks 7 and 8 with other reviews, and
    Task 11 with Task 10**, all on disjoint files. Cost: none seen.

## Known gaps

- **The dogfooding week is not run.** The exit criterion is the human's; so are the
  checklist's GUI checks.
- **Test gate.** A blocked source still loads in a new VM after a handoff or crash
  (ruling 4). Other `Server.reload` entry points bypass the gate. Saves made during a long
  gate run are not coalesced. A TestGate crash loses the blocked set (logged).
- **Reload status does not carry across a VM handoff.** The new VM shows the handoff node,
  and its reload node starts empty.
- **Rejected beams accumulate.** Each rollback leaves its bad beam under
  `_build/dev/herdr_reload/rejected/`, and each selfhost run adds one.
- **Unguarded telemetry.** `HerdrReload.Telemetry.event/2` is called outside the guard, so
  a bad edit to it can break Store restart or the Guard failure path (documented in
  editing-live.md).
- **A demo-mode flake.** `tty_harness.py demo` failed in 2 of 6 full `live-check` runs
  and in 1 of 5 standalone runs at load average about 11. Both failures came after
  `kill %1; fg` of the stopped demo job ("timed out waiting for restore / prompt after kill
  %1"). The demo runs `mix herdr_term.demo` (app.config only) through
  `scripts/tty_guard.sh`, and M7 changed none of that path. It looks like a pre-existing,
  load-sensitive race; a rerun passes.
- **Noisy test output.** `mix test` output carries `herdr-event` info lines and three
  pre-existing compiler warnings (herdr_server test_helper, actions_test, snapshotter_test).
- **Where live-check runs.** Inside a pane, `just live-test` and focused `mix test` are
  safe. The full `just live-check` (tty harness and smokes) runs from another worktree,
  or with the dogfood instance stopped. The smokes `mix run` into the shared `_build/dev`.
- **One instance per log.** Two brokers writing the same log file produce false
  `broker_died` losses in `log_summary.py`.
- **Deferred minors** from task reviews are in the ledger; the final review triaged them
  all as fine to carry.

## Dogfooding start procedure

```sh
# once: a checkout of herdr-live at this branch's merge, toolchain as in AGENTS.md
cd <checkout>
export HERDR_LIVE_LOG=$HOME/.local/state/herdr-live/dogfood-$(date +%F).log   # one log per day (optional)
just live-run                 # = cd live && mix compile && exec live/bin/herdr-live
# work inside it: prefix is ctrl+b; ctrl+b v / ctrl+b - split; ctrl+b q quits
# from another terminal (or a pane):
live/bin/herdr-live status            # broker, primary/standby, last handoff
live/bin/herdr-live rollback [n]      # undo the newest reload batch(es)
live/bin/herdr-live kernel-restart    # after a NIF/kernel change
live/bin/herdr-live test-on-save on   # optional gate (about 0.8 s per save)
# agents inside it: edit live/apps/**, watch the status line (r<N> <k>m, rolled back, synced),
#   run `just live-test` or focused tests; the full `just live-check` runs outside the instance
# end of each day:
python3 live/scripts/log_summary.py "$HERDR_LIVE_LOG"     # or: just live-log-summary
# the week passes when every day's summary ends with: exit_criterion: session_losses=0 -> OK
# and docs/herdr-live/results/m7-manual-checklist.md is filled in
```

Read [editing-live.md](../editing-live.md) first (status texts, what reloads and what
needs `kernel-restart`, re-saving after a rollback, troubleshooting by log grep).
