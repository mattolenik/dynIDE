## Scene contract summary

Binding text is in the moduledocs of `HerdrScene.*`; this is the short form.

- `%Scene{size: %{cols, rows}, panes, chrome: Node, focus: %{pane, chrome}, cursor}`.
  `cursor` is the host-level cursor, filled for inline clients; ref clients derive
  it from the focused pane's cached cursor.
- `Scene.Pane{id, rect, border, rows, cursor, overlays, graphics}`. `rect` is the
  content rect (exactly the pane's grid). `border` is `%{rect, edges, title}` or
  nil. `rows` is `{:ref, pane_id, layout_gen}` or `{:inline, [{n, binary}]}`.
  `cursor` is `%{x, y, shape, visible}` relative to `rect`.
- `Scene.Node{role, id, rect, text, token, props, children}`. Roles: `:root :status
  :tabs :tab :text :button :divider :group :spacer :sidebar :modal`. Tokens:
  `:default :accent :muted :focus :warning :error :inverse`. No glyphs or colours;
  props are open (the mode and hint nodes carry structured `props`).
- `Scene.Overlay{kind, args}`: `:selection :dim :link_hover :scrollbar`, pane-relative.
- `HerdrScene.Event`: `{:key, %{key, mods, event, text}}`, `{:mouse, %{kind, button,
  x, y, mods, px}}` (x/y in scene cells), `{:paste, bin}`, `{:focus, bool}`,
  `{:resize, %{cols, rows, cell_px}}`, `{:chrome, path, action}`. Named keys
  `:enter :tab :backspace :escape :up :down :left :right :home :end :page_up
  :page_down :insert :delete :f1..:f12`, otherwise one grapheme. `mods` is a
  sorted, deduplicated subset of `[:alt, :caps_lock, :ctrl, :hyper, :meta,
  :num_lock, :shift, :super]`. Buttons: `:left :middle :right :none :wheel_up
  :wheel_down :wheel_left :wheel_right`.
- Protocol. Client to server: `{:attach, %{kind: :term | :gui, transport: :ref |
  :inline, size, cell_px, caps, client}}` via `GenServer.call(Protocol.endpoint(), _)`
  (`:herdr_client_endpoint`), reply `{:ok, session_pid, %{rows: {m, f, a}}}`
  (`validate_attach_reply/1`); `{:input, from, seq, event}`; `{:detach}`. Server to
  client: `{:scene, scene}`, `{:damage, pane_id, content_gen}`, `{:rows, pane_id,
  content_gen, [{n, bin}]}` (inline), `{:notice, %{level, text}}`, `{:ack, seq}`,
  `{:handoff, map}`, `{:detached, reason}` (task 16, additive; the session is gone
  after it), `{:input_mode, :terminal | :prefix | :resize}` (ruling 53, additive:
  this client's own input mode, sent to the input's `from` pid before the ack of the
  event that changed it).
- Rows MFA: `{HerdrServer.Pane.Rows, :fetch, []}`; the client calls
  `apply(m, f, [pane_id | a])` and gets `{gen, rows_tuple, cursor} | nil`, where
  `cursor` is the pane-relative `%{x, y, shape, visible}`. The row cache is ETS
  `:herdr_pane_rows`, objects `{pane_id, gen, rows, cursor}`, written by
  `Pane.Server` from `dirty_rows/1`, so clients never consume the vt's
  consume-on-read damage.
- Generations: `{:ref, id, gen}` carries the layout generation (bumps on resize);
  `{:damage}`/`{:rows}`/fetched `gen` carry the content generation (the vt damage
  gen). They are unrelated and clients must never compare them. A restarted
  `Pane.Server` does not bump the layout gen; it resubscribes, which forces full
  damage, so clients re-fetch.
- Fast path: `Store` publishes `:persistent_term.put(Protocol.fast_path_key(), %{gen,
  pane, write: {M,F,A} | nil, intercept: MapSet, passthrough})` when focus, modal
  state or keybinds change; `passthrough` is shared state only (a focused pane, no
  modal). A key goes the fast path iff the client's own input mode is `:terminal`
  (from `{:input_mode, _}`; the Session checks its `Client.State.mode`) and
  `passthrough and write != nil and {key, mods} not in intercept`, calling `Pane.Input.key/2`
  (encode_key + pty write) from the client's own process. After any slow-path
  event the client holds later events until its `{:ack, seq}`, so `"\x02v"` in
  one chunk splits correctly.
- Transport behaviour. Ref: the scene holds `{:ref, id, layout_gen}`; the client
  fetches rows by MFA and re-fetches only damaged panes, new panes and panes whose
  ref gen changed; ref scenes carry no cursors and damage does not re-push the
  scene. Inline: the Session fills every pane with its full rows and cursor on each
  scene push, sends `{:rows, ...}` on damage, and re-pushes the filled scene when
  the focused cursor moves (heavy, optimized in M16). Inline rows in a scene
  replace the pane's cache only when non-empty.

## Deviations from design.md "NIF interfaces" (M1/M2 must know)

Behaviours are in `herdr_server/lib/herdr_server/kernel/{vt,pty,keeper}.ex` and
`herdr_term/lib/herdr_term/kernel/{tty,blit}.ex`.

Server side, after task 15: `HerdrServer.Kernel.{Vt,Pty,Keeper}` are M1's API
verbatim (names, arities, argument and return shapes, event shapes, mode atoms);
see `docs/herdr-live/results/m1.md` "Kernel API". `Native.Vt` and `Native.Pty`
declare `@behaviour` (one line each, so the compiler checks them); `Native.Keeper`
does not (it is a GenServer with `@impl true`, so the declaration would need `@impl`
on four more functions); `test/kernel/native_contract_test.exs` asserts all three
Native modules export every callback. Behaviour-level differences from design.md
that remain:

- `Vt.cursor/1 :: %{x, y, visible, blinking, shape} | nil` (shape
  `:block | :bar | :underline | :block_hollow`) is M1's addition. `Pane.Server`
  maps `:block_hollow` to `:block` (the scene's shapes are `:block | :underline |
  :bar`) and stores nil as is. `feed/2` and `rows_since/2` are not in the behaviour
  (unused by M3).
- `Keeper` (M1 addition): `open(spec) :: {:ok, id}` allocates the kernel id;
  `spec = %{cmd, args, env, cwd, cols, rows, max_scrollback, subscriber}`;
  `lookup(id) :: {:ok, %{vt, pty, os_pid}} | :error` from ETS; `close/1`; `ids/0`.
  M3 passes `max_scrollback: 10_000_000` (bytes) and `subscriber: nil` (the
  `Pane.Server` subscribes in `init/1`).
- Pane ids stay allocated by `App.Actions`. `Pane.Rows` owns a second ETS table
  `:herdr_pane_kernel` (`{pane_id, kernel_id}`, written by the Store on open,
  deleted on close); `Pane.Input` resolves pane -> kernel id -> resources with two
  ETS reads in the caller's process, and `Pane.Server` keeps `kernel_id` in its
  state and matches events on it, re-tagging exit and title with the pane id.
- `Pty.spawn/8` takes the id as its second argument; events carry the kernel id;
  `write/2 :: :ok | {:error, :backpressure | :closed | :too_large}`; `kill/2` takes
  `:hup | :term | :kill | :int | pos_integer`; exit status is
  `n | {:signal, n} | {:panic, bin} | :unknown`. `:osc`, `:dcs`, `:bell`, `:pwd`
  are received and ignored by `Pane.Server` (M8+).
- `encode_key/2` and `encode_mouse/2` take the event map, not the
  `HerdrScene.Event` tuple, and reject modifiers other than `:shift :ctrl :alt
  :super` and the `:none` button (ArgumentError). `Pane.Input` unwraps the tuple,
  drops the other modifiers (`:caps_lock :hyper :meta :num_lock`), maps `:none` to
  nil, and drops (with the rate-limited warning) any event the kernel still
  rejects.
- `mode/2` takes M1's atoms (`Pane.Input` uses `:bracketed_paste`);
  `kitty_keyboard_flags/1` may be `{:stale, n}`; `graphics_placements/1` has one
  argument.
- Children inherit the VM's OS environment, not `System.put_env/2` changes
  (verified: a variable put with `System.put_env` is empty in the child), so the
  Store passes `config :herdr_server, :pane_env` (default `[]`) as the spawn env.
  The kernel itself sets `TERM=xterm-256color`.
- `Kernel.Fake.*` follow the same API; the fake keeper's `lookup/1` is still a
  `GenServer.call` (tests only) and it has a test hook `fail_next_open/1`.

Terminal side, after task 16: `HerdrTerm.Kernel.Tty` is M2's `HerdrTerm.Native.Tty`
API verbatim (`open(%{path, kitty_flags})`, `restore/1`, `size/1`, `subscribe/2`,
`write/2 :: :ok | {:error, :backpressure}`, `stats/1`, `kitty_keyboard/1`,
`suspend/1 :: :ok | {:error, :restored | posix}`; events `{:tty_input, bin}`,
`{:exit, :tty, :hangup | {:panic, bin}}`, `{:tty_resumed}`), and `Kernel.Blit` is
`Native.Blit.frame/3 :: :ok | {:error, :bad_frame}` with M2's seven shape atoms.
Both Native modules declare `@behaviour` (one line each);
`herdr_term/test/kernel/native_contract_test.exs` asserts the Native and Fake
modules export every callback. Differences from design.md and gaps in M2's API:

- design.md has `open/0`; M2's is `open/1` with a map. `Tty.Owner` passes
  `%{path: "/dev/tty", kitty_flags: 1}` merged with the client's `tty_opts` map
  (tests: `size`, `kitty`, `error` hooks on the fake).
- Events carry the constant `:tty`, not a resource id (fine for one tty per client).
- `size/1` raises instead of returning an error; after a hangup a SIGWINCH would
  crash `Tty.Owner` (the hangup already ends the local client).
- M2 writes the alt screen enable at open and has no API to open without it, so the
  terminal client cannot own 1049 itself; restore always resets every mode M2 knows,
  so the client's own disables before restore are redundant but kept (ruling 48).
- `suspend/1` stops the whole OS process, server included (M2 known gap); M3 binds
  no key to it.
- Blit has no OSC 8 link table (M2 ruling 13): hyperlinks are not emitted.

Server tolerances (unchanged): `Pane.Server` logs a warning and keeps running on
non-`:ok` from `resize`, `set_hidden`, `subscribe`; `mode/2 {:stale, _}` is
handled.
