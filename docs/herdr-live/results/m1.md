### 2. 100 MiB `cat`, `mode/2` from a normal scheduler never blocks > 1 ms

`stall_test.exs` (`@moduletag :stall`, timeout 300 s, runs in the default
suite). It writes 100 MiB of numbered 79-column lines to `System.tmp_dir!()`,
opens `/bin/sh -c "cat <file>"` in an 80x24 pane via `Keeper.open`
(`max_scrollback: 1000`, subscriber the test process), and loops
`Vt.mode(vt, :bracketed_paste)` back to back, timing each call with
`:erlang.monotonic_time(:microsecond)`. Samples go to a preallocated
`:atomics` histogram (1 us buckets), so the loop does not allocate. It drains
its mailbox without blocking and calls `Vt.dirty_rows/1` on each damage. It
stops on `{:exit, id, 0}`.

Passing run (captured by `just live-check` at `5f671695`):

```
STALL count=3242350 p50_us=0 p99_us=1 p999_us=1 max_us=100 stale_frac=0.1902 cat_wall_ms=842 damages=205
```

Another run (`mix test --trace`):

```
STALL count=3437520 p50_us=0 p99_us=1 p999_us=1 max_us=403 stale_frac=0.1932 cat_wall_ms=844 damages=205
```

**The assertion `max_us < 1000` is flaky.** Maxima over 23 runs of the
committed test: 833, 544, **4382**, 232, 214, 844, 100, 403, 697, 748, 134, 105,
130, 955, 123, 75, 920, **2647**, 453, 94, 73, **2017**, 338 (3 failures; 4 more
runs sit between 833 and 955). The p50/p99/p999 are 0/1/1 us in every run; the
tail is isolated single samples. About 15-20 percent of calls return
`{:stale, _}` (the parser held the lock), which is the designed fallback and
costs no wait.

Diagnosis (throwaway copy of the test, not committed):

- `:erlang.system_monitor(self(), [{:long_gc, 1}, {:long_schedule, 1}])` on the
  test process reported nothing in 8 runs, two of which had max 1481 and
  2733 us. So no GC pause or long-running schedule slice above 1 ms.
- Replacing `Vt.mode` with `:erlang.phash2(vt)` (no NIF, no lock) in the same
  loop under the same cat load: max_us of 25, 2150, 41, 427, 942, 26, 108, 268,
  367, 118, 30, 314 over 12 runs. A 2150 us outlier with no NIF in the path.
- `mode` uses `try_lock` and falls back to the snapshot, so it cannot wait on
  the reader's lock by construction.

Conclusion: the outliers are not attributable to the NIF. They appear with a
no-op in the timed region too, most likely the scheduler thread being
descheduled by the OS (or the BEAM switching to another process between the two
clock reads) while `cat`, the reader, and writer threads saturate cores. The
bound of 1 ms is therefore not reliable on a loaded desktop host, independent
of kernel code. The threshold was not raised. Options for the owner: accept the
bound as p99.9-style (assert on p999) or run the test on an otherwise quiet
machine, or bind the measuring process to a dedicated scheduler.

## Rulings

Ledger order. Each: decision, then cost if wrong.

- `Pty.resize` takes per-cell px `{w,h}` like `Vt.resize`; the NIF multiplies by cols/rows for `ws_xpixel`/`ws_ypixel`. Cost: a one-line change if M3 wants totals.
- Unchanged re-encoded rows keep their old gen (`dirty_rows` omits byte-identical rows even after `mark_all_dirty`), so clients get fewer bytes. Consumers needing all rows use `full_rows` or the read-cursor reset. Cost: a one-line change if a consumer depends on a gen bump.
- `link_at` and `graphics_placements` run on DirtyCpu (they take the blocking core lock; a full refresh may exceed one chunk). Cost: a dirty-scheduler hop only.
- `encode_mouse` returns nil for `:move` unless any-motion mode 1003 is on, as terminals do. Cost: none expected.
- Damage rule: emit immediately if at least 4 ms since the last damage, else defer with poll timeout equal to the remainder of the 4 ms (the plan's poll(0)-quiescence rule produced 46 damages in 96 ms). Still at most 1 per 4 ms while flowing and immediate after any 4 ms of quiet. Cost: up to 4 ms extra latency on a second keystroke within 4 ms; a timer tweak if M6 latency numbers suffer.
- Writer uses the shared nonblocking master fd and waits on EAGAIN in 50 ms steps (O_NONBLOCK is shared across dups). Cost: up to 50 ms extra latency when the child's input buffer is full.
- Task 5 review: approved with 8 minors; minors 1-7 went back as fix round 1 (load-bearing for Task 6 contracts and Linux CI). Cost: one extra round.
- ECHILD exit maps to `ExitStatus::Unknown`, delivered as `{:exit, id, :unknown}` (event shape extended). Cost: a match clause for consumers.
- Task 6 installs a no-op panic hook at NIF load (panics reach the BEAM via the exit event or a NIF raise; the default hook would write stderr). Cost: panic backtraces are lost from logs.
- NIF load fails if SIGCHLD is SIG_IGN or SA_NOCLDWAIT (auto-reap would break per-pid waiting). Cost: a load failure on exotic VM configs, which is the correct loud failure. Superseded by the next ruling.
- Supersedes the SIGCHLD ruling: ERTS (OTP 29) itself sets SIGCHLD to SIG_IGN|SA_NOCLDWAIT; NIF load resets it to SIG_DFL (no handler installed) and fails only if auto-reap persists. `erl_child_setup` reaps its own port children, so erts is unaffected. Cost: if a future OTP relies on auto-reaping its direct children, at most a zombie; the alternative is a double-fork reaper helper.
- A late-subscriber race may deliver `exit` before `damage` (exit still exactly once). Cost: a consumer that needs damage-before-exit ordering must handle either order.
- Task 6 review: needs fixes (1 important: duplicate exit on same-pid resubscribe; minors); fix round 1 dispatched. `vt_feed` moves to DirtyCpu (unbounded replay input). Cost: a dirty hop for tests.
- Test-only NIF gating is a runtime gate, not a cargo feature: one `.so` serves all mix envs (rustler writes a single `priv/native/herdr_kernel.so` shared by dev and test through the priv symlink, so dev compiles silently dropped test-nifs and broke `mix test`). `test_inject_reader_panic` is always compiled and enabled only when the module's load_data says test. Cost: inert test code in the prod binary.

Rulings the brief lists that have no ledger line (decisions as implemented):

- Grapheme strategy: inline up to 12 UTF-8 bytes, longer clusters overflow into a per-row trailer (canonical, so equal cells give equal rows). Cost: a format change if real content needs more inline.
- Record width 32 bytes (12 glyph, fg/bg/ul u32, attrs u16, width u8, link u32); 15 full 200x50 panes are about 4.8 MB per full repaint. Cost: bandwidth; widening breaks the golden vectors.
- `read_text` runs on DirtyCpu (screen with scrollback can be large). Cost: a dirty hop per call.
- Snapshot structure: `Arc<Snapshot>` of `{gen, cols, rows[{gen, bytes: Arc<[u8]>}], cursor, modes[], kitty_flags, scrollbar}` rebuilt under the core lock after each chunk; BEAM reads clone the Arc outside the lock. Cost: one rebuild per chunk, bounded by the damage-based re-encode of changed rows only.
- Damage coalescing without a timer thread: the reader's poll timeout is the remaining part of the 4 ms window (see the damage ruling). Cost: coarser than a dedicated timer.
- Reaping by a per-pid `waitpid` thread; exit fires on reap, not on EOF (`exit_on_reap_not_eof`). Cost: one thread per live child.
- Mode table is a fixed name-to-number list; scalar reads use `try_lock` and return `{:stale, v}` from the snapshot when the parser holds the terminal. Cost: a consumer may act on a value up to one chunk old.
- OSC 52 payload cap 1 MiB, other OSC and DCS caps 4096 bytes; over-cap payloads arrive as `{:truncated, binary}`. Cost: large clipboard or DCS payloads are cut.
- `dirty_rows/1` is a single-consumer cursor (one shared read cursor per vt); `rows_since/2` is stateless and any number of consumers may use it. Cost: two consumers sharing `dirty_rows` steal each other's rows; use `rows_since` for the second.

## Kernel API for M2, M3 and M5 owners

All facades are in `HerdrServer.Native.{Vt,Pty,Keeper}`; types are `vt`/`pty`
opaque references. Do not call `HerdrServer.Native` directly.

### Specs (copied from the sources)

### Events

Sent to every subscriber pid. `id` is the id given to `Pty.spawn` (the Keeper
pane id).

```
{:damage, id, gen}
{:exit, id, status}      status :: non_neg_integer | {:signal, signo} | {:panic, binary} | :unknown
{:osc, id, code, payload}  code never 0, 1, 2, 7; payload :: binary | {:truncated, binary}
{:dcs, id, payload}        payload :: binary | {:truncated, binary}
{:bell, id}
{:title, id, binary}       OSC 0 and OSC 2
{:pwd, id, binary}         OSC 7 raw payload, e.g. "file://host/tmp"
```

`:unknown` is the ECHILD case (status lost). `exit` is delivered exactly once
per pty; a late subscriber may see it before or after the full damage.

### Resource ownership (Keeper)

`Keeper` is a GenServer that creates the `vt` and `pty` and owns the pane-id
table, a named protected ETS set (`HerdrServer.Native.Keeper`,
`read_concurrency: true`). `Keeper.open(spec)` allocates the next id, builds
`Vt.new` + `Pty.spawn` (a failed spawn inserts nothing) and, when `subscriber`
is set, subscribes it. Other processes read the table directly with
`Keeper.lookup(id)` -> `{:ok, %{vt:, pty:, os_pid:}}` or `:error`, with no call
through the GenServer, and may then call `Vt.*`/`Pty.*` on the references from
any process. `Keeper.close(id)` sends `:hup` and deletes the row; the exit
event still follows. `lookup` raises if the Keeper is not running.

### `dirty_rows` and `rows_since`

- Rows are `{gen, [{row_index, packed_row}]}`; row indices are viewport rows
  `0..rows-1`; binaries are per `docs/herdr-live/packed-cells.md`.
- `dirty_rows/1` returns rows changed since the previous call and advances one
  shared read cursor on the vt. Single consumer only. A second call with no new
  output returns `{gen, []}`.
- Rows that re-encode to byte-identical binaries keep their old gen and are
  omitted, even after a full-damage mark (resize, resubscribe, `set_hidden`
  false). Use `full_rows/1` for every row, or `rows_since(vt, gen)` for a
  stateless cut (rows whose gen is newer than `gen`).
- `gen` is monotonic per vt; `{:damage, id, gen}` carries the snapshot gen at
  emission.

### Resubscribe semantics

`Pty.subscribe(pty, pid)` monitors `pid` and always resets the read cursor and
requests a full damage, which is sent to all current subscribers. A dead
subscriber is dropped by the monitor; a new subscribe then gets full damage
(`dirty_rows` returns all rows, byte-identical or not, because the cursor is
reset). If the child already exited, the retained exit follows the damage and is
not resent to a pid that already received it. Unhiding a pane sends full damage;
hidden panes keep parsing but emit no damage.

### Input encoding

`encode_key(vt, event)` with
`%{key: atom | binary, mods: [:shift | :ctrl | :alt | :super], event: :press | :release | :repeat, text: binary | nil}`.
`key` is a named-key atom (`:enter :tab :backspace :escape :space :up :down
:left :right :home :end :page_up :page_down :insert :delete :f1..:f24 :kp_0..:kp_9
:kp_enter :kp_add :kp_subtract :kp_multiply :kp_divide :kp_decimal :kp_equal`) or
a one-character binary (`"a"`). Unknown keys raise `ArgumentError`. Output
respects cursor-keys mode and kitty flags (`"\e[A"` for up, `<<3>>` for ctrl+c).

`encode_mouse(vt, event)` with
`%{kind: :press | :release | :move | :drag | :scroll, button: :left | :middle | :right | :wheel_up | :wheel_down | :wheel_left | :wheel_right | nil, x: non_neg_integer, y: non_neg_integer, mods: [mod], px: {number, number} | nil}`.
Returns nil when the child is not tracking (for example `:move` unless mode
1003), else the bytes (`"\e[<0;1;1M"` for a left press at 0,0 under 1000+1006).
`px` is used for SGR-pixels (1016) when the cell size is known.

`encode_focus(vt, bool)` is `""` unless focus events (1004) are on, then
`"\e[I"` / `"\e[O"`.

### Mode atoms

`:cursor_keys :origin :wraparound :cursor_blinking :cursor_visible :mouse_x10
:mouse_normal :mouse_button :mouse_any :focus_events :mouse_utf8 :mouse_sgr
:alternate_scroll :mouse_sgr_pixels :bracketed_paste :synchronized_output
:grapheme_cluster :color_scheme_report :alt_screen`. An unknown atom raises
`ArgumentError`. `mode/2` and `kitty_keyboard_flags/1` return `{:stale, v}`
(snapshot value) when the parser holds the lock.

### Other

- Scheduler classes: `spawn`, `read_text`, `feed`, `link_at`,
  `graphics_placements` on dirty schedulers; everything else on normal ones.
- Writes: queue cap 1 MiB, a write is accepted whenever the queue is empty;
  otherwise `{:error, :backpressure}`; after exit `{:error, :closed}`.
- M5 (kernel restart): the fd and thread model are in `pty.rs`; the reaper is
  a per-pid `waitpid` thread and NIF load resets SIGCHLD to SIG_DFL, so a
  handoff design must preserve both.

## Known gaps

- Exit criterion 2 (1 ms stall bound) is flaky on a loaded host, about 3 failures in 23 runs, with outliers also seen with no NIF in the timed region. See criterion 2.
