## Rulings

Each gives the decision, then what it costs if wrong. Plan decisions 1-10 are in
[plans/m10.md](../plans/m10.md); the ones that matter are restated.

1. **The field stays `Scene.Pane.graphics`** (design.md), `graphics_placements` is the `Native.Vt` name. Cost: a rename if a later contract wants the long name.
2. **Placements travel in the scene through `Pane.Facts`**, refreshed on every publish and announced only on change. Cost: a placement may trail its rows by one session repaint window (16 ms).
3. **Host ids** `10_000 + phash2({pane, image, fp}, 900_000)` and `1 + phash2({pane, image, placement, piece}, 900_000)` (herdr's ranges). Cost: a hash collision shows the wrong image (not detected, as herdr).
4. **Every placement is replayed every frame that has any** (herdr). Cost: a few hundred bytes per frame with images on screen.
5. **Media**: direct `t=d` for small images and outside Ghostty; `t=t` client temp files over 32 KiB with herdr's environment gate (also `HERDR_PANE_RUNTIME_ID`), a probe, a 10 s consumption timeout and a 16 MiB file cap. herdr's server-exported `t=f` path with host OK responses is not ported. Cost: no zero-copy file path for very large local images; a non-Ghostty host always gets base64.
6. **Occlusion**: a dimming modal hides every image; menus, toasts, non-dimming modals and pane overlays (selection, search matches, copy cursor, link hover, scrollbar column) crop images into pieces. Cost: images vanish while a confirm/prompt/settings modal is open (herdr crops).
7. **No offscreen retention**: an image no visible piece uses is deleted and re-uploaded when it returns (herdr keeps 16 / 64 MiB). Cost: a re-upload after a tab switch, scroll-off or dimming modal.
8. **Remote cap 8 MiB per image** (configurable), placeholder above. Cost: large photos show as `[image WxH]` on socket clients.
9. **Cleanup by delete-all** on Render attach/reset/failure and on tty restore; **suspend keeps host images** (the alt screen it returns to still has them, and Render's cache stays valid). Cost: images stay on the alt screen while the client is suspended.
10. **Implicit placements** (ghostty internal id 0) get `u32::MAX - n` per image; other ghostty ids pass through. Cost: see Known gaps (one collision case).
11. **Superseded frames' graphics ops are merged and coalesced in the blitter** (drop everything before a delete-all, drop superseded places when the new frame places, drop an upload paired with a later delete of the same id), relying on Render uploading an image only while the host lacks it. Cost: a future Render that violates that assumption could lose an upload during a stall.
12. **A frame whose rows fail to decode still writes its graphics ops.** Cost: none seen.
13. **The scripted check normalizes herdr's scrollbar gutter** (clip herdr-live to width - 1). Cost: the check cannot catch a real off-by-one in a pane's last column.
14. **Tasks 3 and 7 ran in scratch worktrees in parallel and were cherry-picked**; tiny follow-ups (Task 1, a 9-line Task 4 fix) were reviewed by the owner reading the diff. Cost: a missed nit.
15. **Pane layer**: popups win over base panes for images, and keep their images under a dimming modal; a pane's overlays crop only its own placements. Cost: a popup image shows while a dimming modal is open (the modal box still covers it).

## Known gaps

- **Implicit vs explicit placement ids**: ghostty's C API does not say whether a placement id was chosen by the child or is its own counter, so an implicit placement whose internal id is k collides with an explicit `p=k` of the same image (only one shows). Fix shape: expose ghostty's implicit/explicit flag as a placement data key in `crates/ghostty-vt` (a vendored libghostty-vt patch if the C API lacks it) and number implicit placements separately from explicit ids.
- **Images do not survive a kernel handoff or persistence**: the ghostty snapshot carries no kitty state and the restored vt has no cell pixel size until the next resize; after `kernel-restart` the host is cleaned (no ghost) but images are gone until the child sends them again. M8's VT-text scrollback has no images either. For M17/M18.
- **One placement geometry per pane**: ghostty computes placements with the driving client's cell pixel size; a second client with a different cell size gets the same cell rects and source crops (pixel offsets may be off by a fraction of a cell).
- **No in-VM size cap**: a large direct upload is copied from the kernel to Render and to the blitter (DirtyCpu copy in the kernel, a normal-scheduler copy in the blit NIF, about 1 ms per 8 MiB).
- **Remote**: no per-scene byte budget (many new near-cap images go out in one flush and stall that conn until sent); a held-across-handoff conn may resend images it had queued; a persistent guard failure sends one error notice per scene.
- **Render**: cell pixel size is re-read only when the grid size changes (a font change alone keeps the old one); the Render struct is at credo's field limit.
- **Facts**: a `Pane.Facts` write while the table is being recreated is dropped and the placements are re-published only on their next change.
- **Blit**: `DeletePlacement` ops are not coalesced during a host stall (bounded by placements created); leftover temp files of a crashed client are removed only at the first file upload of a later client.
- **Ghost test** swaps the module with `Code.compile_string`, not through the Watcher's rollback path.
