## Rulings

Each gives the decision, then what it costs if wrong.

Plan rulings:

1. **One viewport per pane, owned by ghostty.** A client's scroll moves it for every
   client on that pane (tmux copy-mode semantics); selection, hover, copy mode and drag
   are per client. Cost: a per-client viewport needs a kernel history-read path.
2. **No reserved scrollbar gutter.** The scrollbar overlays the rightmost content column
   only while scrolled back (herdr narrows the pty by one column). Cost: the last
   column of long lines is hidden while scrolled; a gutter later changes every pane's pty
   width.
3. **Pastes up to 16 MiB through a retrying per-pane queue; larger ones rejected with a
   notice; embedded `ESC[201~` removed** (herdr: 1 MiB, marker passed through). Cost:
   up to 16 MiB held per pane queue; a queued paste cannot be cancelled (Known gaps).
4. **Foreground client** (bell, child OSC 52, host colours) = the session that most
   recently handled slow-path input or attached. Cost: with several clients the bell or
   clipboard can go to the one the human is not looking at.
5. **Host colours become ghostty's default colours per pane**, so ghostty answers OSC
   10/11/12/4 in order; kitty keyboard, DA/DSR/DECRQM/XTVERSION/XTGETTCAP stay ghostty's.
   Raw C1 XTGETTCAP is not supported. Cost: a program using raw C1 XTGETTCAP gets no
   answer; per-pane colour overrides by the foreground client's host only.
6. **DECSCUSR: a cursor equal to a fresh vt's default is sent as `:default`.** Cost: an
   explicit `CSI 2 q` (steady block) shows the user's own cursor style (no
   "explicitly set" bit in libghostty-vt).

Ledger rulings (`.superpowers/sdd/m9/progress.md`):

7. Pointer hover is `%{pane: id, link: ...}` (View needs the pane). Cost: a field rename.
8. `.superpowers/sdd/m9` (ledger, briefs, reports) is never committed. Cost: lost on
   `git clean`.
9. Task 1 (published contract) reviewed by the controller reading the ~60-line validator

## Known gaps

- **Copy-mode search miss costs ~1.1 s** over 20_000 rows, inside that client's session
  (above).
- **`page_up` fidelity flake**: 1 failure in 15 runs, at load 25 -> 148, screen never
  captured (guess: `ESC [ 5 ~` split at the ESC hitting the 25 ms flush).
- **A queued paste cannot be cancelled**: Ctrl-C is queued behind it (order kept).
- **Focus move ends copy mode** (herdr pauses and resumes it). New output does not clear
  search matches; a resize or alt-screen switch does not drop the copy selection; only
  the viewport's matches are kept (herdr: at most 1024); absolute rows drift once the
  scrollback is at capacity; mouse wheel in copy mode is not reflected in its `top`.
  No test for the "copy mode failed" notice path.
- **Focus report on pane switch** always sends Gained to the new pane (herdr sends Lost
  when the host window is unfocused).
- **Facts**: `scroll` in `Pane.Facts` is stale while the pane is unscrolled (read only
  when scrolled; the new stream bench reads the vt for that reason); cwd, title and
  progress changes write facts but do not dispatch `{:pane_facts}`; `Facts.put` is
  check-then-insert; set_color_scheme runs before set_colors; a stale `{id, nil, n}`
  facts row is possible only if pane ids were reused (they are not). The facts table is
  missing in a VM that hot-loads M9 without a Mirror restart (guarded: skipped and
  recreated). Cwd is tracked but shown nowhere yet (Persist uses it as a fallback).
- **Host colours**: no caps at all if the host answers nothing; partial answers send
  `nil` for the missing values (M13 must expect them); a host that ignores DSR 5n waits
  for the 5 s window. OSC 52 writes over 192 KiB are refused with a warning (the desktop
  tool takes any size).
- **Pointer**: every mouse event fetches rows and modes for the hit pane (slow path, per
  client); scrollbar drags are folded rather than throttled to 33 ms; `scroll_lines` and
  `copy_on_select` are hard-coded (3, true: herdr's defaults; no config yet); no direct
  test for a failed autoscroll tick; one ETS read per damage while a selection exists;
  the fake `link_at` is always nil, so OSC 8 opening is tested at the unit level only.
- **Overlays**: scrolled rows with other overlays are decoded twice; `accent/1` sets fg
  unconditionally; the `drop_stale` path (recompute failure) is untested.
- **Kernel/fakes**: `poll_text` uses a fixed 50 ms margin in `vt_m9_test`; hard-coded
  ids 9101-9104; the fake vt's LF at the bottom does not push history (`set_history`
  does); fake `read_text({:rows, _})` unguarded for negatives; the desktop reaper
  spawn-failure path is untested.
- **Paste**: a paste started during handoff `:begin` is still queued (the truncation
  notice covers a loss). `Pane.Server` is 481 lines (extract a WriteQueue later).
  `Pane.Server` calls `File.dir?` on each OSC 7 cwd.
- **Not ported**: herdr's macOS Option-as-Alt non-ASCII table for legacy panes.
- **Session repaints** still go through `Store.snapshot/0` (throttled to 60/s per
  session); repainting from the session's last seen app would need the app in
  `Client.State`.
- **Pre-existing warning**: `api/conn.ex:122` "clauses with the same name and arity
  should be grouped together" (`defp line/3`, M12 code from herdr-live) prints on every
  compile.
- **Scene typespec**: `Scene.t` shows the cursor `blinking` as required though it is
  optional.

## Notes for other milestones

- **M10 (kitty graphics)**: pane overlays are emitted in a fixed order by
  `View.Overlays.pane/3`: scrollbar, selection, link_hover, then copy mode's search
  matches and copy cursor. The client applies them per row in
  `HerdrTerm.Client.Term.Render.Overlays.apply/5` (`ctx = %{w, h, focused}`), folding
  restyles in list order and drawing the scrollbar last over column w-1. Image
  placements should decide where they sit in that order (under the selection, above
  the scrollbar column or not). `apply(row, [], ...)` is a single clause: keep the
  no-overlay path free.
- **M11 (detection)**: `Pane.Facts.get/1` holds `title` (sanitized), `stripped_title`
  (one leading spinner glyph dropped, as herdr's `title.rs`) and `progress` (OSC 9
  payload). herdr's detection read `latest_title`/`latest_progress`; read them from
  Facts. They do not dispatch `{:pane_facts}` on change; add that if a detector needs a
  push.
- **M12 (API)**: `pane.run` now declares only `not_found` (it is queued; `ok` means
  queued, not written). `send_text` queues behind a pending paste; `send_keys` uses
  `Input.key/3` with `host_scroll: false`, so page keys reach the child. `Api.View`
  keeps reading the session title (same sanitized value as Facts) to stay pure; cwd and
  scroll are in `Pane.Facts` when the pane object wants them.
- **M13 (chrome)**: `{:caps, map}` from the client: `colors: %{fg, bg, palette}` and
  `scheme`, where any of fg, bg, scheme may be `nil` (partial host answers); a later
  scheme-only update is `{:caps, %{scheme: s}}`. The status-line mode label is `COPY`
  (accent) or `/query` / `?query` while a search prompt is open (`View.mode/2`). Mouse
  events not hit-tested by chrome go to `Client.Pointer` (pure) via `PointerIo`. The
  host now has `?1003h` (any motion) on, so every pointer move reaches the session;
  Input coalesces queued moves (at most one waits), and plain moves over a
  non-tracking pane with no hover/drag resolve to nothing before the Store.
- **M16 (remote attach)**: overlays are semantic and travel in the scene; a socket
  client draws them with the same `Render.Overlays`. The inline row transport carries
  the rows; selection text is read server-side (`read_text`) and sent as
  `{:clipboard, %{text, source}}`. Clipboard writes and `{:open_url, _}` run on the
  **client** machine (`HerdrTerm.Clipboard`, desktop NIF), so a remote client copies to
  its own clipboard and opens links in its own browser; OSC 52 is used when the client
  itself runs under ssh. Bell and child OSC 52 go to the foreground client only.
