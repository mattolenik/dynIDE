# Packed cell format

The row encoding that `Native.Vt.dirty_rows/1` and `full_rows/1` return, that
`Scene.Pane` carries as `{:inline, [{n, row}]}`, and that `Native.Blit.frame/3`
consumes. Owner: M1. Elixir reference: `HerdrScene.Cell`
(`live/apps/herdr_scene/lib/herdr_scene/cell.ex`). Golden vectors:
`live/apps/herdr_scene/test/support/packed_cell_vectors.json`; every encoder and
decoder (Elixir, `herdr_kernel`, `herdr_term`) must pass all of them. Regenerate
with `python3 gen_packed_cell_vectors.py > packed_cell_vectors.json` in that
directory.

## Row

```
row = records ++ trailer ++ trailer_len:u32le
records = cols x 32-byte record (column x at byte x*32)
trailer = UTF-8 of overflow clusters, concatenated in column order
```

`cols = (len(row) - 4 - trailer_len) / 32`. A row with no overflow ends in four
zero bytes, and its records slice and concatenate as plain bytes. A row of zero
columns is the four bytes `00000000`.

## Record (32 bytes, little-endian)

```
 0                              12      16      20      24    26  27  28      32
 +------------------------------+-------+-------+-------+-----+---+---+-------+
 | glyph (12)                   | fg    | bg    | ul    |attrs| w | 0 | link  |
 +------------------------------+-------+-------+-------+-----+---+---+-------+
```

| bytes | field | meaning |
|---|---|---|
| 0..12 | glyph | grapheme cluster as UTF-8, NUL padded. All zero = empty cell (draw a space). |
| | | overflow ref when byte 0 is `0xFF`: bytes 1..4 zero, 4..8 offset u32, 8..12 length u32, into the trailer |
| 12..16 | fg | colour u32 |
| 16..20 | bg | colour u32 |
| 20..24 | ul | underline colour u32 (SGR 58) |
| 24..26 | attrs | u16 bitfield, below |
| 26 | w | width u8: 1 narrow, 2 wide, 0 spacer tail |
| 27 | reserved | zero; decoders ignore |
| 28..32 | link | hyperlink id u32, 0 = none |

Colour u32 = `tag << 24 | payload`:

| tag | meaning | payload |
|---|---|---|
| 0 | terminal default | 0 |
| 1 | palette | index 0..255 |
| 2 | RGB | `r << 16 \| g << 8 \| b` |

So palette 0 is `0x01000000` and differs from default (`0`). RGB (1,2,3) is
stored as bytes `03 02 01 02`.

attrs:

| bit | flag |
|---|---|
| 0 | bold |
| 1 | italic |
| 2 | faint |
| 3 | blink |
| 4 | inverse |
| 5 | invisible |
| 6 | strikethrough |
| 7 | overline |
| 8..10 | underline style: 0 none, 1 single, 2 double, 3 curly, 4 dotted, 5 dashed (the `GHOSTTY_SGR_UNDERLINE_*` values) |
| 11..15 | zero |

## Rules

- Canonical: a cluster of 12 UTF-8 bytes or fewer is always inline; longer
  clusters are always overflow refs. Overflow refs appear in column order with
  increasing offsets and no dedup. Equal cells encode to equal rows, so rows
  can be compared as binaries. Comparing single records that carry overflow
  refs (a blitter's per-cell diff) must compare the resolved trailer bytes,
  not the ref.
- A wide cell (w = 2) is followed by its spacer tail (w = 0, glyph empty). A
  ghostty spacer head (wide char wrapped at the last column) is encoded as an
  empty narrow cell.
- Cursor, selection, dimming, link hover and scrollbars are not in cells; they
  are scene overlays.
- Link ids are interned per `Vt` and stable for its life; they mean nothing
  outside their pane. Chrome cells use 0. Resolve with `Native.Vt.link_at/3`.
- Slicing or concatenating rows that carry overflow refs rebuilds the trailer
  and rewrites offsets (`HerdrScene.Cell.slice/3`, `concat/1`). Rows with an
  empty trailer need no rewriting.

## Rulings

- Width 32 bytes: 12 inline bytes cover combining sequences, flags, skin-tone
  and VS16 emoji and short ZWJ sequences (`👨‍💻` is 11 bytes) without overflow;
  underline colour and a u32 link id fit; records stay 32-byte aligned. 15
  full panes of 200x50 are ~4.8 MB per full repaint.
- Inline glyph is UTF-8, not codepoints, so blitters copy bytes to the tty
  without re-encoding.
- Overflow lives in a per-row trailer, not a per-pane table, so a row is
  self-contained over any transport and needs no kernel state to decode.

## Vectors

`packed_cell_vectors.json`: `{"record_size": 32, "vectors": [{"name", "cells",
"hex"}]}`. Each cell has every field (`glyph` string, `fg`/`bg`/`ul` as
`"default"`, `{"palette": n}` or `{"rgb": [r, g, b]}`, `attrs` list of flag
names, `underline` style name, `width`, `link`). `hex` is the whole row,
lowercase. A conforming implementation encodes `cells` to exactly `hex` and
decodes `hex` to exactly `cells`. The vectors were generated by an independent
Python encoder, not by the Elixir module they test.
