## Config file

- **Path**: app env `config :herdr_server, :config_path`, else `$HERDR_LIVE_CONFIG`, else
  `${XDG_CONFIG_HOME:-$HOME/.config}/herdr-live/config.toml`. This is deliberately not
  herdr's path (ruling 5).
- **Format**: herdr's TOML. Keys:
  - `[keys]`: catalog action names and `prefix`, with string or array values in herdr key
    syntax.
  - `[ui]`: `sidebar_width`, `sidebar_min_width`, `sidebar_max_width`,
    `sidebar_start_collapsed`, `confirm_close`, `status_indicators`, `prompt_new_tab_name`.
  - `[ui.sound]`: `enabled`, `command`.
  - `[ui.toast]`: `delivery`, `delay_seconds`.
  - `[theme]`: `name`, `auto_switch`, `light_name`, `dark_name`.
  - Top level: `onboarding`.
  - Unknown `[ui]`/`[theme]` keys and other tables are ignored.
- **Onboarding**: a missing file means `onboarding: true`, so the onboarding modal opens at
  the first init. A file opens it too unless it sets `onboarding = false`.
  - Enter, Right, `l` or `continue` dismisses it and writes `onboarding = false`. Esc, other
    keys and the backdrop do nothing.
  - If that write fails, a warning is shown and onboarding returns on the next reload or
    restart.
  - The test env, `tty_harness.py`, `launcher_smoke.sh` and `attached_smoke.sh` use a
    temporary file with `onboarding = false` (ruling 18).
- **Precedence** (ruling 16): file values win over the persisted Ui for every key the file
  sets. Keybinds are always the defaults plus the file (M8 does not persist them).
  - Every settings, onboarding and capture change is written to the file, so nothing the
    user chose reverts.
  - A key removed from the file keeps its running value on reload instead of reverting to
    the default (final review minor 6).
- **Failure handling**:
  - An undecodable or unreadable file loads as `failed: true`. On reload or adopt, the
    running config stays as it is and one `config: <reason>` warning goes to every
    subscriber (ruling 17). On a fresh start, herdr-live runs on the defaults with that
    warning.
  - An invalid entry (unknown action, bad key spec, bad value, min > max) keeps its current
    value and adds one diagnostic. herdr actions that herdr-live lacks (`workspace_picker`,
    `zoom`, `switch_tab`, custom commands) therefore warn on a shared herdr config.
  - Diagnostics are kept for late subscribers until a clean load.
  - Writes are a line-based in-place upsert. Every other line is kept byte for byte.
    `[[array]]` headers end a table.
  - A write goes to a tmp file beside the resolved symlink target and is then renamed over
    it, with the mode kept. A failed write warns the origin.
  - Ceilings: a trailing comment on a replaced line is dropped. Dotted keys, inline tables
    and `"""` strings covering the same key are not understood. The tmp cleanup after a
    failed rename is untested.

## Rulings

Each ruling gives the decision, then what it costs if wrong. Rulings 1-7 are the ledger's
up-front list; 8-29 are its `Ruling:` lines, in order.

1. **Fixtures stay in `herdr_scene/priv/fixtures/scenes`** (the M3 convention), not
   `test/fixtures` as the brief worded it. Cost: a directory move.
2. **A permanent full-width bottom status row** (herdr has none) carries the reload status
   and the mode, with `TERMINAL` at column 0. Cost: one row of pane area compared with
   herdr.
3. **The modal stack stays shared in `App.Focus`** (design.md State layout); no ADR. Cost:
   two clients share one prompt.
4. **Toasts are per client (`Client.State`), alerts are protocol messages, agent facts
   are shared.** Cost: none recorded.
5. **The config path is `herdr-live/config.toml`, not herdr's**, so dogfooding beside
   herdr does not clobber herdr's config. TOML via hex `toml ~> 0.7` (decode only), with our
   own writer. Cost: a herdr user copies the file over once.
6. **Chrome actions are `{kind, %{x, y}}`; bare-atom actions are rejected** (none was in
   use). Cost: none recorded.
7. **Sidebar prefs are shared in `App.Ui`** (herdr keeps them per client); the pane area is
   shared anyway. Cost: two clients cannot have different sidebar widths.
8. **The onboarding stub**: Task 7 added the optional `ignores_escape?/1` callback and
   tested it with a test-only kind, and Task 8's Onboarding sets it. This avoids a fake kind
   in lib. Cost: none.
9. **Tasks ran in order T1..T13**, since the dependencies are linear. Cost: none.
10. **The alert kind is narrowed to `:notification`** because M9 owns `{:bell, pane_id}`,
    which avoids two bell paths. Cost: none.
11. **Task 10 consumes M9's `{:caps, %{colors, scheme}}` plumbing.** M9 owns the host
    OSC/DSR queries in Input. Task 10 adds only Detect, the palettes and resolution. Cost:
    it waits on M9 or falls back to `COLORFGBG`.
12. **Chrome hit-testing stays client-side in the term client (Hit + Input).** Non-chrome
    mouse events pass through unchanged to Session, where M9's `Client.Pointer` routes
    them. Cost: none.
13. **The region rule**: a region role below an ancestor with a rect needs no rect of its
    own. This keeps the fixtures valid. Cost: a GUI must lay out nested regions itself.
14. **Root props `%{theme, indicators, mouse}` are emitted from Task 4 and extended in
    Task 10**: the contract lists them, though Task 2's brief did not. Cost: none.
15. **Prefix-mode keycap hints in `View.Status` went to Task 4**, since the client already
    draws them. Cost: none.
16. **The chrome layout is cached by `{chrome, size, theme}`.** A reload of a Chrome
    module shows at the next chrome change, and the reload notice always causes one. Cost: a
    reload with notices off would not repaint (there is none today).
17. **The sidebar agent line is the agent, else the pane title, else `terminal`**; the
    contract wins over the brief. Cost: none.
18. **Clicks fire on press (the plan), not on release (herdr)**: simpler, with no
    click-vs-drag ambiguity on non-drag hits. Cost: drag-reorder later needs release
    semantics.
19. **There is no 33 ms drag throttle**; each drag is one Store event. Cost: a pty resize
    per cell while dragging.
20. **The dim-modal frame is accepted at 2.8x the no-modal frame**, about 0.6 ms and only
    while a dimming modal is open. Caching it needs a Compose restructure shared with M9.
    Cost: about 0.4 ms extra per frame while a modal is open.
21. **Modal and menu rects are computed by the server (View)**, since regions carry rects
    per the contract. Cost: a GUI that wants other sizes must ignore them.
22. **Capture rule**: a key after the prefix becomes `prefix+key`; a ctrl/alt/super chord
    becomes a direct bind; any other key becomes a prefix bind. This gives a way to make
    direct binds. Cost: a plain direct key cannot be bound (it would steal typing anyway).
23. **Config precedence on restart**: config-file values win over the persisted Ui for
    every key the file sets. Keybinds come from defaults plus the config, since M8 does not
    persist them. The file is the user's declared intent. Cost: a settings change not
    written to the file would revert (every settings write goes to the file).
24. **An undecodable file keeps the current config**, as herdr does. Cost: none.
25. **The test env config is an existing per-run file with `onboarding = false`** (this
    supersedes the plan's nonexistent path), which keeps the suite deterministic. Cost: one
    temp file per run.
26. **API `tab.close`/`pane.close` keep M12's "fresh tab" semantics, while chrome closes
    the workspace**, because the API is M12's contract. Cost: two close behaviours until
    M12 and M13 align (flagged to the coordinator).
27. **Task 10 adds no host queries to Input**, because M9 owns them and had not landed.
    Render accepts the client-internal `{:caps, %{colors, scheme}}` (the same shape as the
    protocol caps update) and reads `COLORFGBG` at start. M9's Input should also send its
    caps map to Render. Cost: light/dark auto-detection only via `COLORFGBG` until M9 lands.
28. **Task 11 leaves the pane bell entirely to M9** (its `{:bell, pane_id}` and Pane.Server
    forwarding), with no `{:pane_bell}` event, which avoids two bell paths. Cost: the bell
    works only once M9 lands.
29. **API requests bypass the modal guard; only keybindings are dropped under a modal.**
    API callers and agents must not wedge behind a modal, and modal targets re-check their
    ids. Cost: an API change can alter state beneath an open modal; a Confirm or Prompt
    whose target the API closed no-ops when answered.

## Known gaps

- **The side-by-side review is not done.** The verdicts are the human's (table above).
- **Hot-reloading M13 into a running pre-M13 VM rolls back** (`ui.sidebar` KeyError). M13 reaches a running dogfood
  instance only through a restart. The mirror, carry and rollback paths all run
  `App.Upgrade.app/1`. Old apps also keep their old keybinds (no `prefix+b`) until the
  config is loaded.
- **Two close semantics** (ruling 26): a chrome close that removes a workspace's last tab or
  pane closes the workspace (after a confirm when `confirm_close`). The API's
  `tab.close`/`pane.close` replace the last tab with a fresh one in the same workspace.
  `Actions.close_pane`/`close_tab` called directly also keep the fresh-tab behaviour.
- **`sound.command` is a trust boundary for M16.** The scene's root props carry the
  configured command, and the terminal client runs it. A socket client must not execute a
  server-supplied path: M16 must make it a client-local pref or allowlist it.
- **The bell and host theme queries are left to M9.** Render consumes `{:caps, map}` and
  `COLORFGBG`, but herdr-live sends no OSC 11 or DSR 996 itself, so auto light/dark works
  only via `COLORFGBG` until M9's Input forwards its caps. The pane bell works only with
  M9's `{:bell, pane_id}`.
- **Agent states and labels need M11.** Nothing sends `{:agent_state, id, state}` yet, so
  badges show `unknown`, there are no notifications or `● menu` dots, agent lines show the
  title or `terminal`, and alerts title unlabelled agents `agent` (herdr sends none without
  a label).
- **Not done**:
  - `:system` toast delivery and the 1 s toast delay;
  - mobile layout (cols <= 64);
  - the Go to navigator and navigate mode (`prefix+w`);
  - worktrees;
  - release notes;
  - drag-reorder of tabs and workspaces;
  - hover highlights (menus included);
  - the settings `integrations` section;
  - the agents sort label;
  - tab bar position and hide-when-single-tab;
  - the `pane_borders` setting;
  - zoom;
  - the `custom` keybind group and rebinding indexed `switch_tab`.
- **Input under a modal**: keys that `Client.Keys` resolves locally (the prefix key, user
  direct binds) never reach a modal; only capture bypasses Keys. Right and middle presses
  on chrome let their release pass to a pane. A fast double press on `+` with
  `prompt_new_tab_name = false` opens two tabs (a double click counts as a click). While
  capturing, presses skip `swallow`, so a release can reach a pane if the modal closes
  between the press and the release.
- **Persist**: a v3 snapshot written by a pre-fix `live/m13` build has no pane `name` and
  fails `{:invalid, :panes}` on restore (v3 is unreleased).
- **Config ceilings**: see "Config file" (a removed key keeps its running value; trailing
  comments; dotted keys and inline tables; untested tmp cleanup).
- **Deferred minors carried by the final triage**, from
  `.superpowers/sdd/m13/final-review.md`, all judged fine to carry:
  - Upgrade defaults `size` to 80x24 when it keeps the old area (nothing calls in-VM
    `code_change` today).
  - A dead width cap in `frame.ex`. `toggle_sidebar` flips `collapsed` while the sidebar
    is hidden. A pre-existing `press/3` test warning.
  - `:chrome_retry` gates every relayout for up to 500 ms. A hard-coded client-side
    attention glyph. Weak test coverage of badge colours.
  - The status region has no hit. The App.Chrome moduledoc is stale. The sidebar split
    press/release drifts the ratio. List offsets are not re-clamped after closes.
    `Actions.reframe` is public.
  - `Modal.mod` raises on an unknown kind atom (Esc still pops). The new-tab prefill
    duplicates the free-number logic. `Menu.split` and `Prompt.create_tab` match strictly
    on `{app, []}`.
  - Capture can overwrite keys that are not in the catalog. `to_config` emits `prefix`.
    Dead `:meta`/`:hyper` chord entries. The theme current mark ignores `auto_switch`.
  - The late-subscriber notice code. Per-run TMPDIR config files accumulate. The
    `store_adopt` test ignores panes. A toml dep compile warning. Diagnostics for unknown
    herdr actions.
  - The terminal palette's `:muted` is overlay0, not `:faint`, so the `terminal` theme is
    not byte-identical to the M3 look. No RED was captured for palettes, detect and some
    rasterizer tests.
  - The toast moduledoc line. `Chrome.required_props(:divider)` reports only the `:path`
    form.
  - The pre-existing `api/conn.ex:122` warning (M12).
- **Shared files over budget**: `store.ex` (+28 for config, +6 for requests) and
  `session.ex` (about +60 for toasts) grew past the plan's ~40-line guideline. The policy
  itself lives in `App.Store.Config` and `Client.Toasts`.
