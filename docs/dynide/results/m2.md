### The destructor restores the terminal when `terminate/2` is skipped

`tty_destructor.exs` runs in a VM launched like `bin/herdr-live`: `-noshell -noinput`, stdin `/dev/null`, with the pty as its controlling tty.

1. A bare `spawn`ed process opens the tty and holds the only reference to it. The script confirms the tty is in raw mode.
2. The script kills that process with `Process.exit(pid, :kill)`, so no `terminate/2` runs, and then forces GC.
3. The script polls `stty -g`, with PENDIN masked, until it matches the pre-open value.

To show the check proves something, the destructor's reset was temporarily removed: the harness then went red.

- the NIF `{:error, :bad_frame}` path

## Rulings

Each ruling gives the decision, why, and what it costs if wrong.

1. **One output thread per tty encodes Blit frames and performs every host-tty write.**
   - Why: the retained frame then always equals what was actually written.
   - Cost if wrong: none found.
2. **"Behind" means a new frame arrives while the previous frame is still pending.**
   - The new frame replaces the pending one, `repaint` is OR-ed, and the drop is counted. Frames never queue.
   - Raw `write/2` bytes go into a FIFO capped at 1 MiB. A write that would exceed the cap returns `{:error, :backpressure}` and is not queued. A single write over 1 MiB is always refused.
   - Cost if wrong: callers must handle backpressure.
3. **The output thread and the reader poll in 100 ms slices and re-check shutdown, so neither ever blocks indefinitely.**
   - macOS `poll(2)` rejects `/dev/tty` (POLLNVAL), so macOS uses `select`, with an fd_set sized to the fd.
   - Cost if wrong: none found.
4. **The retained frame is per tty resource, held inside the output thread's encoder.**
   - It is reset after suspend and resume, and after a failed flush. The next frame is then a full repaint with `ESC[2J`.
   - `repaint: true` and resize redraw every cell without `ESC[2J`, as the reference does.
   - Cost if wrong: debris after a resize; the fix is to send `2J` on a size change.
5. **`restore/1` and `suspend/1` run on DirtyIo with a 100 ms write budget, since both are bounded calls.**
   - The destructor makes one non-blocking write of the restore sequence, then resets termios and sets shutdown.
   - It never joins threads; each thread holds its own Arc.
   - Restore writes the fd directly, not through the output thread.
   - Cost if wrong: on a stalled host the destructor's escape sequence may be truncated. Termios is still restored.
6. **Open and restore sequences:**
   - `open` writes `ESC[?1049h ESC[?7l ESC[?25l`.
   - `restore` pops the kitty flags (only if they were pushed), turns off mouse modes 1000/1002/1003/1006/1016, bracketed paste and focus events, resets OSC 8, SGR and DECSCUSR, shows the cursor, turns autowrap on, leaves the alt screen, then calls `tcsetattr`.
   - No leading CAN byte: the sequence starts with ESC, which aborts a CSI or OSC that is partly written.
   - Cost if wrong: one garbled cell after a host stall.
7. **The kitty probe** sends `CSI ? u` plus DA1 with a 250 ms deadline. The flags are exposed through `kitty_keyboard/1` as an integer or nil.
   - `open(%{kitty_flags: n})` pushes the flags only when the probe confirmed support.
   - Bytes the user typed during the probe are delivered first. Replies that arrive late come in as `{:tty_input, _}`.
   - Cost if wrong: none found.
8. **`open` runs on a kernel thread; the facade waits up to 5 s for its reply.**
   - On a timeout, the facade flushes the reply and restores any tty that arrives late.
   - Cost if wrong: none found.
9. **Suspend runs restore, `kill(0, SIGSTOP)`, re-raw, re-push of the kitty flags, frame reset, then `{:tty_resumed}`.**
   - It holds the write lock throughout, so no output bytes land in cooked mode. The reader keeps running.
   - `{:tty_resumed}` is sent from a short-lived thread, because an OwnedEnv send panics on a scheduler thread. It arrives just after `:ok`.
   - `suspend` returns `:ok` only when `{:tty_resumed}` will follow. Otherwise it returns `{:error, :restored}` or `{:error, posix}`.
   - Cost if wrong: callers must handle an error tuple.
10. **On Linux, suspend also calls a thread-directed `raise(SIGSTOP)` after `kill(0, SIGSTOP)`, but only when `kill` returned in under 10 ms.**
    - Evidence:
      - On Linux, `kill` returns to the calling dirty-scheduler thread in about 27 µs, and that thread re-applied raw mode before the stop reached it (lflag 0xa30 while stopped).
      - macOS stops inside `kill` (156 ms) and would stop twice if it also raised. A `raise` added on macOS made the single-stop assertion fail.
      - The termios saved at open was cooked on both platforms: 0x8a3b on Linux, 0x5cb on macOS.
    - The split is cfg-gated at item level (`stop_process_group`). The 10 ms guard prevents a second stop when the caller was already stopped inside `kill`.
    - Cost if wrong: BSDs are unverified, and under extreme load a slow `kill` return skips the raise.
11. **The VM's own death by kill -9 is recovered by the `dynide/bin/live-demo` wrapper.**
    - The wrapper saves `stty -g` before the VM starts, and afterwards restores it and writes the restore sequence.
    - It traps HUP, INT, QUIT and TERM so it outlives a signalled job.
    - The resource destructor is proven separately, by the `:kill` test.
    - `bin/herdr-live` will need the same wrapper once M3 attaches the terminal client, because no destructor runs on kill -9 or `System.halt`.
    - Cost if wrong: a terminal left raw after a kill.
12. **Cell decoding exists only in `cell.rs`.**
    - Equality uses the resolved glyph bytes, never trailer offsets. Byte equality of a whole row is a valid fast path.
    - Palette colours are always written as `38;5;n` / `48;5;n`.
    - Underline colour uses `58;5;n` or `58;2;r;g;b`.
    - attrs map to SGR 1, 2, 3, 5, 7, 8, 9 and 53. Underline styles map to `4` and `4:2` through `4:5`.
    - Cost if wrong: a few extra bytes per SGR.
13. **Blit emits no OSC 8.** Cells carry only link ids, which are resolved per `Vt` with `link_at`. The link id still takes part in cell equality.
    - Cost if wrong: M3 adds a link table argument to `frame/3`.
14. **Blit is the trust boundary to the host terminal.** A glyph that contains C0, DEL or C1 is drawn as a space, and the frame is not rejected.
    - Cost if wrong: a legitimate glyph containing a control byte renders blank.
15. **`frame/3` rejects bad input as follows.**
    - A bad frame shape returns `{:error, :bad_frame}`.
    - A malformed term (not a list, or an index above 65535) raises badarg.
    - Row bytes are copied into the job, marked with a `ponytail:` comment.
    - Cost if wrong: one memcpy per frame.
16. **After `restore`, the resource is finished.**
    - `write/2` returns `:ok` and discards the bytes, and frames are counted as dropped.
    - The reader stops.
    - Cost if wrong: a caller cannot tell its writes are discarded.
17. **Errors reach Elixir as posix atoms** (`:enoent`, `:enotty`, …), with `{:os_error, n}` or a string as fallbacks.
    - `size/1` raises with the posix reason if the fd stops being a terminal.
    - Cost if wrong: none found.
18. **The fake row source is `HerdrTerm.Demo.FakeRows`, a pure module that encodes with `HerdrScene.Cell`.**
    - The demo is a Mix task that no supervisor starts.
    - The real M1 wiring (a `Vt` pane into Blit) is left to M3 or the gate.
    - Cost if wrong: one demo module to swap for real rows.
19. **Pty testing:**
    - Rust tests use `libc::openpty` and open the slave through `open_path`. The test helper uses `ttyname_r`, because glibc's `ttyname` shares one static buffer across threads.
    - End to end, a python3 stdlib `pty` harness runs inside `live-check`. The destructor VM is launched like `bin/herdr-live`.
    - Cost if wrong: python3 becomes a test-time dependency.
20. **Smaller choices:**
    - `serde_json` is a dev-dependency only.
    - `plt_add_apps: [:mix]` is set, because the Mix task lives in lib.
    - The wrapper's log override is `LIVE_DEMO_LOG`.
    - Cost if wrong: none.
21. **The manual check in a real GUI terminal is deferred to a human** (procedure above).
    - Cost if wrong: quirks of real terminals stay unobserved until that run.
22. **Process.** Each task had a fresh implementer and a task review. The final whole-branch review (opus) asked for fixes, which went in as a single fix wave followed by a scoped re-review, which came back clean.

## Known gaps

These were deferred by review and do not block merge.

- **Suspend stops the whole VM.** When M3 hosts the server in the same VM, kernel threads stop during a suspend. PTY children in their own sessions keep running.
- **Events carry the constant `:tty`, not a resource id.** That is fine for one tty per client.
- **A failed `set_raw` on resume is swallowed and not logged.** The crate has no `tracing` dependency.
- **The output queue has no item cap.** `VecDeque::remove` is O(items) under the queue lock, and many tiny writes within the 1 MiB budget make that slow.
- **A width-2 cell with an empty glyph leaves a stale column.** Such a cell is malformed input.
- **Restore bytes may land after a CSI that a stalled host only partly received.** A frame encoded before a stop can paint as a diff after resume; the next frame is a full repaint.
- **Wrapper edge cases:**
  - The wrapper's `printf` restore runs even when the VM never entered the alt screen.
  - A job sent to the background with `bg` stops on its `stty` (SIGTTOU).
  - The symlink and log-path block is duplicated from `bin/herdr-live`.
- **Test gaps:**
  - The panic path (`{:exit, :tty, {:panic, _}}`) has no test.
  - Some Rust tests are timing-based: the 20 ms drop bound and `superseded_repaint_is_kept`.

## For M3

**`HerdrTerm.Native.Tty`** (`dynide/apps/dynide_term/lib/dynide_term/native/tty.ex`):

- `open(opts \\ %{}) :: {:ok, t} | {:error, posix | {:panic, String.t()} | :timeout}`. Options: `:path` (default `"/dev/tty"`), `:kitty_flags` (default 0).
- `restore(t) :: :ok`. Idempotent; the resource destructor also restores.
- `size(t) :: {cols, rows, px_w, px_h}`. Raises `ErlangError` with a posix reason if the fd is not a terminal.
- `subscribe(t, pid) :: :ok`. Input buffered so far is delivered first.
- `write(t, iodata) :: :ok | {:error, :backpressure}`
- `stats(t) :: %{frames_written, frames_dropped, queued_bytes}`
- `kitty_keyboard(t) :: non_neg_integer | nil`
- `suspend(t) :: :ok | {:error, :restored | posix}`

Events sent to the subscriber:

- `{:tty_input, binary}`
- `{:exit, :tty, :hangup}`
- `{:exit, :tty, {:panic, binary}}`
- `{:tty_resumed}`

After `{:tty_resumed}`, send a frame (it repaints fully). Re-send any mouse, bracketed-paste or focus modes you enabled, because the restore sequence turned them off. Kitty flags are re-pushed for you.

**`HerdrTerm.Native.Blit.frame(Tty.t(), [{n, row}], %{cursor: {x, y} | nil, shape: shape, repaint: boolean}) :: :ok | {:error, :bad_frame}`**

- `rows` must be `0..h-1` in order, with the same non-zero column count in every row. Each row is a packed row as defined in `docs/dynide/packed-cells.md`.
- `shape` is one of `:default | :block_blink | :block | :underline_blink | :underline | :bar_blink | :bar`.
- The call does not wait for the host. The newest frame wins and superseded frames are dropped.

**SIGWINCH:** call `:os.set_signal(:sigwinch, :handle)`, then add a handler to `:erl_signal_server` with `:gen_event.add_sup_handler/3` (see `Winch` in the demo task). On each `:sigwinch`, call `size/1` and send a frame with `repaint: true`.

**Running the demo:** `just live-demo` or `dynide/bin/live-demo`, which runs `mix herdr_term.demo` under `-noshell -noinput` with stdio sent to the log. Keys: `q` or Ctrl-C quits, Ctrl-Z suspends.

**Fake row source:** `HerdrTerm.Demo.FakeRows.frame(cols, rows, %{tick, last_input, pid})`.

**Headless switch:** `HerdrTerm.Application` is still inert, so M3 owns the headless switch and the move of the stty-restore wrapper into `bin/herdr-live`.
