# M8 results: persistence and session restore

Branch `live/m8`, rebased onto `herdr-live` at 4f2e97d7 (M9 and M13 contracts, M13's
`App.Upgrade`). Plan: [plans/m8.md](../plans/m8.md). ADR: [0002](../adr/0002-scrollback-persistence.md).

## What landed

| brief item | what | commits |
|---|---|---|
| 1. `Persist.Writer` | `HerdrServer.Persist.Writer`, the last child of the server supervisor (so it stops first). It polls the ETS mirror every second and writes only when the snapshot changed. Scrollback is written every 60 s for panes whose content changed, and for all panes at clean stop. A final write runs in `terminate/2`; the shutdown is 10 s. It never writes while a handoff phase is `:begin` or `:released`, and it rewrites after an aborted handoff. Every disk and kernel call goes through `HerdrReload.Guard`, and errors are logged once per reason. Format: ETF, `<dir>/session.<name>.etf`, schema v2 (`Persist.Schema`), with a migration hook (`@migrations`, v1 -> v2 registered). The schema is explicit (no struct literals, so no compile-time fan-out), plain data only (`Schema.plain?/1` checked before every write), and keybinds and the modal stack are never stored. Writes are atomic: an exclusive temp file in the same dir, 0600, sync, rename. Stale temp files are swept at start. | 17a85926, 03e2a455, dc8b2c4a, d2c4da67, 9ffdd575, 8dea6485, 8733d37b, c0939b48 |

## Exit criteria

- **Stop, start, identical layout and cwds.** `python3 dynide/scripts/tty_harness.py persist`, in `just live-check`, 22 PASS lines.
  - Run 1 runs `bin/herdr-live` attached in a pty and splits, with `cd dir-b; echo m8-marker-b` in the new pane, then a new tab with `cd dir-c`. It goes back to tab 1 and quits.
  - Run 2 uses the same state dir. Its log has `persist_restore source=disk reason=boot panes=3 scrollback=3 ms=35`, `m8-marker-b` is on screen from the replayed history, and `pwd` in the focused pane prints `dir-b`.
  - Run 2 then rewrites the file: `saved_at` is newer and `persist_writes >= 1`. The two dumps (`dynide/scripts/persist_dump.exs`: workspaces, tabs, layout trees with ratios, focus, prev_focus, active ids, size, every pane's cwd) are equal: `PASS: persist: stop, start, identical layout and cwds (dump A == dump B)`.
- **Fixed point.** `property "snapshot -> restore -> snapshot is a fixed point"` in `apps/herdr_server/test/persist/schema_test.exs` (StreamData, 300 runs). Apps are built from `Actions.init` plus 0..30 random splits, tab ops, closes, cycles and resizes, with random UTF-8 titles and facts. It also asserts `plain?` and a `[:safe]` ETF round trip. A separate test covers an all-defaults app with every M13 Ui field. StreamData (`~> 1.1`, test only) is justified in 17a85926.

## Rulings (made on the human's behalf)

1. **The persisted cwd is the shell's OS cwd** (new NIF), with OSC 7 as the fallback. M9's `Pane.Facts` (OSC 7 cwd) can become a further fallback once it lands. *Cost if wrong:* one source to swap in `Persist.Facts`.
2. **Restore spawns `$SHELL` and never re-runs the recorded command.** *Cost if wrong:* M11/M12 add opt-in re-run or resume later.
3. **ETF with an explicit, versioned plain-term schema, not the in-memory structs.** In-memory refactors do not break disk, and `[:safe]` decode refuses unknown atoms (with a preload retry). *Cost if wrong:* the files are not human-readable; `persist_dump.exs` prints them.
4. **`Schema.plain?/1` accepts any atom**, so Ui fields persist generically. *Cost if wrong:* an atom from a removed theme quarantines the file once.
5. **Keybinds and the modal stack are not persisted;** restore uses `Keybinds.default()`. *Cost if wrong:* user keybind edits made at runtime are lost on restart (none exist today).
6. **`session.size` is persisted and migrated** (coordinator instruction; schema v2). Nothing updates `App.Session.size` yet, so it stays 80x24 on disk (note for M13). *Cost if wrong:* none.
7. **The disk restore calls `App.Upgrade.app/1` under `run_twice`** after `Schema.restore` (coordinator instruction). *Cost if wrong:* none.
8. **The Writer polls the mirror (1 Hz, change-only) instead of subscribing to the Store.** That gives zero Store coupling and picks up cwd-only changes. *Cost if wrong:* up to about 1 s of layout lost on a whole-host crash; a clean stop writes the final state.
9. **Scrollback policy** per ADR 0002, last 1000 rows of VT. *Cost if wrong:* a config default.
10. **The broker signals the fallback with a FRESH reason byte** rather than handing the VM the last carry blob, because the carry blob may be what failed 3 adoptions. *Cost if wrong:* up to about 1 s staler layout after a fallback.
11. **A decoded-but-unrestorable file, or one whose restore crashed the Store, is moved aside, not overwritten.** *Cost if wrong:* a good file can be set aside by an unrelated Store exit during the restore window; it is kept and can be restored by hand.
12. **A second instance is isolated by defaulting `HERDR_LIVE_STATE_DIR` under a set `HERDR_LIVE_RUNTIME_DIR`, not by a lock file.** *Cost if wrong:* a user who sets only a runtime dir for their main instance starts once with an empty session dir.
13. **`tail_ansi` counts content rows** (blank padding below the last content row is dropped) and is clamped to 10 000. *Cost if wrong:* none seen.
14. **The persist smoke lives in `tty_harness.py`** (new `persist` mode in live-check) rather than in `attached_smoke.sh`, because it needs typed input. *Cost if wrong:* none.

## Known gaps and carried minors

- **Restore timing.** A restore blocks the Store in `handle_continue` for about 19 ms per pane. Client calls queued behind it would time out only past 5 s.
- **File handling.**
  - The temp file is created under the umask and then chmodded to 0600. This matters only for a user-chosen state dir that is not 0700.
  - There is no directory fsync after the rename.
- **Small races.**
  - A residual race between the Writer's last phase check and the rename at PREPARE. The content equals the frozen state, and the new VM rewrites.
  - A restored pane can be recorded with `cwd: nil` for one poll if the OS lookup fails right after spawn.
- **Untested or untouched paths.**
  - No store-level test of `reason=fallback`; the two halves are unit-tested.
  - The `dogfood-sample.log` fixture keeps the old `disk_restore_not_implemented` reason, as history.
  - Kitty images are not persisted (a VT tail carries no image placements).
- **ADR 0002 wording.** Its "10-15x" figure for full ANSI is partly extrapolated, and the bench labels the tail row `full(14044)` although it is clamped to 10 000.

## Notes for other milestones

- **M13:** `App.Ui` fields persist generically if they are plain data. `App.Session.size` is persisted but nothing sets it from a client yet. A new session fact needs a `Persist.Schema` field plus a migration (`@migrations`, bump `version/0`).
- **M9:** `Pane.Facts` cwd and title can feed `Persist.Facts.collect/2` as fallbacks. The Writer never reads rows (`Pane.Rows.gen/1` is a `lookup_element`).
- **M12:** the API can expose the persisted command, cwd and title, and a "restore from file" command could call `Persist.Load`. Telemetry kinds are `persist_*`.
- **M11:** agent resume on restore would hang off the recorded `command` and cwd. Today restore always starts `$SHELL`.
- **M17:** the broker as reaper and adopted exit status are unchanged, as the brief allowed.
