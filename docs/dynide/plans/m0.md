# M0 Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A buildable, testable Elixir umbrella plus two Rustler NIF crates under `dynide/`, with a headless launcher, `just live-*` recipes, CI, and a fork CLAUDE.md.

**Architecture:** Mix umbrella `dynide/` with apps `herdr_scene` (pure contracts, no deps), `herdr_server` (NIF crate `dynide/native/dynide_kernel`, links `crates/ghostty-vt`), `herdr_term` (NIF crate `dynide/native/dynide_term`). Each NIF crate is its own Cargo workspace. A shell launcher boots the VM `-noshell -noinput` with stdio redirected to a log file.

**Tech Stack:** Erlang/OTP 29, Elixir 1.20.4, Rustler (Hex `~> 0.38.0`, crate `=0.38.0`), credo `~> 1.7`, dialyxir `~> 1.4`, Rust toolchain from root `rust-toolchain.toml` (1.96.1), Zig 0.16.0, just.

**Spec:** `docs/dynide/design.md` (The split, Repo layout, Scene contract, State layout, Hot reload/Compilation) and `docs/dynide/milestones.md` M0 section.

## Global Constraints

- Worktree `/Users/matt/herdr-project/herdr-live-worktrees/m0`, branch `live/m0`. Never push. Lowercase conventional commits, no emojis, no co-author lines.
- Do not break `cargo build` at the repo root. Do not edit `crates/ghostty-vt` or `vendor/`.
- Module namespaces: everything in an app lives under that app's root module: `HerdrScene.*`, `HerdrServer.*`, `HerdrTerm.*`. Design names map by prefix (design `Native.Vt` -> `HerdrServer.Native.Vt`, `Native.Tty` -> `HerdrTerm.Native.Tty`).
- NIF module per crate: `HerdrServer.Native` (crate `herdr_kernel`), `HerdrTerm.Native` (crate `herdr_term`). Later `Native.Vt`/`Native.Pty` are Elixir facades over that one NIF module.
- Each NIF crate: own `[workspace]` table (independent of root workspace), `crate-type = ["cdylib"]`, `[profile.dev] panic = "unwind"` and `[profile.release] panic = "unwind"`, committed `Cargo.lock`.
- `consolidate_protocols: Mix.env() == :prod` in every app (false in dev and test).
- No app writes to stdout when run via the launcher; no production `unwrap()` in Rust.
- `mix credo --strict`, `mix dialyzer`, `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check` must all be clean.

## Review Focus

- First boot from a clean tree compiles Rust and Zig inside `mix run`: that output must land in the log, not the terminal (Task 4 smoke runs from a cold `_build` in the clean-state run).
- SIGTERM while the VM is still compiling/booting must still exit and not leave the tty altered (Task 4: launcher uses `exec` so the signal reaches the VM; stdin is `/dev/null`).
- Log directory does not exist yet: launcher must create it (Task 4 smoke uses a fresh temp dir).
- Adding a future app (e.g. `herdr_gui`) that depends on `herdr_server` must fail the dependency test (Task 1 test discovers apps by listing `apps/`, not a hardcoded list).
- `just live-check` invoked from any directory, including `dynide/`, must work (Task 5 uses `source_directory()`).
