# M17 Long Tail Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every "do" row of the M17 inventory with a commit and a test; the
dropped and deferred rows are closed by the inventory text itself.

**Architecture:** Small, separate modules per item, plus small additive edits to the
landed shared files (`App.Actions`, `App.Session`, `View`, `Layout`, `Config`,
`Api.Spec`, `HerdrCli.Argv`). Shell items (tty restore, log summary) stay in
`dynide/bin`, `dynide/scripts`.

**Tech Stack:** Elixir 1.20 / OTP 29 umbrella under `dynide/`, POSIX sh, Python 3 (log
summary, tty harness), Rust only where M9's desktop NIF is reused (wave 4).

**Spec:** [results/m17-inventory.md](../results/m17-inventory.md) (row ids A1..D18 below),
AGENTS.md, design.md. The coordinator rulings at the end of status.md bind: C1 is
cleared; D4 and anything touching `Scene.Pane` or the Render pane rasterization waits
for M9; B7 belongs to M14 and is dropped here; B3 waits for M14's
`{:spawn, id, size, opts}` cmd/args/env commit; `type = "plugin_action"` calls
`HerdrServer.Plugins.Keybind.mfa(command) :: {m, f, a}` (M14).

## Global Constraints

- Every app callback begins `state = Map.merge(%Struct{}, state)`; shape changes get
  `code_change/3`; no `fn` in state; keybinds are MFA.
- New session facts persisted only with a `Persist.Schema` field + migration (bump
  `version/0`); this plan persists only C2's workspace `auto_name` flag and D6's pane
  `agent_session`, both in one schema v4 (Task 9 adds v4; Task 21 adds its field to
  the same unreleased v4).
- The server emits no glyphs, colours or escape sequences; the client writes OSC.
- No new dependency. No OS branches in Elixir: OS-specific tools run from NIF crates
  (wave 4) or are POSIX-generic (`git`, `sh`).
- Blanket rescue only in `HerdrReload.Guard`; `System.cmd` calls from the Store path
  run under `Guard.run` with a budget or in a Task, never inline in a callback.
- Commit per task, lowercase conventional subject, explicit paths, no co-author.
- Every task ends with `cd live && mix format --check-formatted && mix test` for the
  touched apps green; Task 26 runs the full gate.
- Golden scene fixtures change only in their own commit with the reason in the body.
- Edits to `api/spec.ex` regenerate `docs/dynide/api.md` (`cd live && mix herdr.api.docs`)
  and keep `cli_conformance_test.exs` green.

## Review Focus

1. **A SIGTERM to the launcher still stops cleanly** after the tty_guard wrap (smokes
   and `herdr-live` SIGTERM contract). Task 1 test: launcher_smoke still passes and the
   new harness mode also checks a plain SIGTERM exits with the tty cooked and no
   `broker_killed` line.
2. **Headless runs never touch a tty**: `HERDR_LIVE_HEADLESS=1` must bypass the guard
   (benches, smokes run under a pty they do not own). Task 1 asserts the launcher's
   headless branch execs the broker directly (grep in launcher_smoke).
3. **Git not installed, not a repo, or a slow repo**: worktree verbs answer `failed`
   with git's stderr, the branch poller shows nothing and never blocks the Store.
   Tasks 10 and 11 test a non-repo cwd and a missing `git` (PATH without it).
4. **Zoom survives closes and splits**: closing the zoomed pane, splitting while
   zoomed, or switching tabs never leaves a zoom id that is not in the layout.
   Task 8 tests each.
5. **Branch names with `/`, spaces, unicode** in worktree slugs and labels. Task 10
   tests `feature/x y` -> `feature-x-y` and `ünï` kept.
