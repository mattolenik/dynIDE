# M9 terminal fidelity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** everything a terminal user expects of a pane works as in herdr: scrollback
scrolling with a scrollbar, mouse and copy-mode selection with clipboard, hover links
and Ctrl-click, OSC side channels (title, cwd, progress, OSC 52, bell, colours and
theme queries), bracketed paste of any size up to 16 MiB, focus reports, query
roundtrips, reflow on resize, and herdr's legacy key fallbacks.

**Architecture:** the viewport stays ghostty's (one per pane, `scroll_to`); the server
publishes per-pane terminal facts (scroll position, cwd, title, progress) in an ETS table
next to the row cache and tells sessions when they change. Per-client presentation
state (selection, hover, copy mode, drag and click timing) lives in `Client.State` and
is resolved by pure modules (`Client.Pointer`, `Client.Words`, `Client.Links`,
`Client.CopyMode`) that `Client.Session` calls through the Guard; `View.Overlays` turns
that state into semantic `Scene.Overlay`s, and the terminal client draws them in a new
`Render.Overlays`. Child OSC events are parsed by a pure `Pane.Osc` in `Pane.Server`.
The kernel gains five small NIFs (colours, colour scheme, selection text, glyph-only
screen rows, modifyOtherKeys) and the terminal NIF two (clipboard write, open URL).

**Tech Stack:** Elixir 1.20 / OTP 29 umbrella (`dynide/`), Rustler 0.38 NIF crates
(`dynide/native/dynide_kernel`, `dynide/native/dynide_term`), wrapper crate `crates/ghostty-vt`,
Python 3 pty harness.

**Spec:** M9 brief (`m9-brief.md` and `wave3-common.md`, coordinator scratchpad),
`docs/dynide/milestones.md` M9, `docs/dynide/design.md` (The split, Scene

specs extracted from tag `herdr-reference` in `.superpowers/sdd/m9/research/*.md`

## Rulings this plan takes (cost if wrong in results/m9.md)

1. One viewport per pane, owned by ghostty (design.md NIF interfaces). A client's
   scroll request moves it for every client showing the pane (tmux copy-mode
   semantics). `Client.State` keeps what is truly per client: selection, hover,
   copy mode, drag state. A per-client viewport would need a kernel history-read path.
2. No reserved scrollbar gutter (herdr narrows the pty by one column). The server emits
   the `:scrollbar` overlay only while the pane is scrolled back; the client draws it
   over the rightmost content column.
3. Pastes up to 16 MiB (`config :herdr_server, :paste_max_bytes`, default 16_777_216,
   equal to `Parse.paste_max/0`) are written whole through a per-pane retrying queue;
   larger events are rejected with a notice (herdr rejects over 1 MiB). Embedded
   `ESC[201~` is removed from bracketed payloads (herdr does not; safer).
4. "Foreground client" (bell, child OSC 52, host colours) = the session that most
   recently handled a slow-path input or attached (`Client.Foreground`).
5. Host colours set ghostty's own default colours per pane (`set_colors`), so ghostty
   answers OSC 10/11/12/4 in order; no reply-rewriting tracker. Kitty keyboard state,
   DA/DSR/DECRQM/XTVERSION/XTGETTCAP stay ghostty's. Raw C1 XTGETTCAP is not supported.
6. DECSCUSR: a ghostty cursor equal to a fresh vt's default style is sent as shape
   `:default` (host keeps the user's cursor); an explicit `CSI 2 q` equal to that
   default is indistinguishable (no "explicitly set" bit in libghostty-vt).

## Review Focus

- Typing (fast path) into a pane that is scrolled back snaps it to the bottom and the
  key is not lost (Task 4, `snap_on_key_test`).
- A 4 MiB paste into `cat > file` arrives byte-exact and keys typed during it arrive
  after it (Task 4, `paste_queue_order_test` with the fake pty reporting backpressure).
- A selection whose pane closes, resizes or scrolls under it never crashes the session
  and is cleared on close/resize (Task 6, `stale_selection_test`).
- A mouse-tracking child (htop, vim): presses, drags and wheel go to the child, no host
  selection; Ctrl+click on a URL still opens it (Task 6, `tracking_child_test`).
- Two clients: one scrolling or selecting does not break the other's scene; bell and
  child clipboard go to the foreground one only (Task 6 `two_clients_test`, Task 3
  `foreground_test`).

  `ctx = %{panes: [%{id, rect}], focused: id | nil, info: %{id => %{tracking: boolean,
  any_motion: boolean, alt_screen: boolean, alternate_scroll: boolean, scroll: map,
  rows: tuple | nil}}, now_ms: integer, scroll_lines: 3, copy_on_select: true}`.
  Actions: `{:forward, ev}`, `{:focus, id}`, `{:scroll, id, delta}`,
  `{:scroll_top, id, row}`, `{:keys, id, [key_event]}`, `{:copy, id, {x1,y1}, {x2,y2}}`,
  `{:open, id, %{id: link_id, x, y} | %{url: binary}}`, `{:autoscroll, id, :up | :down}`,
  `:autoscroll_stop`, `:repaint`.
- Rules (herdr): wheel over a pane: tracking -> `[{:forward, ev}]`
  (Pane.Input snaps); alt_screen and alternate_scroll -> one `:up`/`:down` arrow per
  notch as `{:keys, ...}`; else `{:scroll, id, ∓3}`; an unfocused pane is focused
  first; horizontal wheel only forwarded when tracking. Left press with `:ctrl` on a
  link -> `{:open, ...}` and swallow until the matching release; ctrl+move over a link
  -> hover, any other mouse event clears hover. Tracking child: all other events
  `{:forward, ev}`. Not tracking: left press records `press`, clears the selection;
  drag makes a `:char` selection clamped to the pane rect; release without movement
  is a click; a second click within 350 ms, same pane, <= 1 cell away -> `:word`
  selection (drag extends by words); release with `copy_on_select` -> `{:copy, ...}`
  and (char) clear / (word, no drag) keep 500 ms; pointer on the pane's top/bottom row
  or beyond while dragging -> `{:autoscroll, ...}` (beyond: first jump
  `clamp(3*distance, 3, 15)` lines), back inside -> `:autoscroll_stop`; wheel during a
  drag scrolls and extends. Press on the rightmost column of a scrolled pane ->
  scrollbar: on the thumb drag keeping the grab offset, on the track centre the thumb
  on the row (`{:scroll_top, ...}`). Plain moves with no button over a pane whose
  child is not `any_motion` and no hover/drag -> `[]` (nothing reaches the Store).

  `{:open}` with a link id -> `Kernel.vt().link_at(vt, x, y)` uri; `Links.safe?` ->
  client `{:open_url, uri}`, unsafe ignored, no link -> the saved press and release
  are forwarded; `{:focus, id}` -> `Store.run({Actions, :focus_pane, [id]}, size)`;
  autoscroll timer every 30 ms. Clears selection/hover when its pane leaves the scene
  or its rect size changes. Marks `Client.Foreground` on every slow-path input and on
