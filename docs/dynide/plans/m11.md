# M11 Agent Detection and Agent Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** herdr-live knows what the agent in each pane is doing (idle, working, blocked, done), using herdr's manifests, and exposes it the way herdr does (badges, alerts, `agent.*` API, `pane.agent_status_changed` events, `agent read|explain` CLI).

**Architecture:** Pure modules under `HerdrServer.Detect.*` (manifest parse/validate, region extraction, gate engine, process identification, per-pane tracker state machine) driven by one thin `Detect.Poller` GenServer that ticks over all panes with a per-tick budget, reads the bottom-buffer text only for panes whose kernel activity counter moved, writes `{:agent, id}` rows into `Pane.Facts`, and casts `{:pane_agent, ...}` / `{:agent_state, ...}` events to `App.Store`. Two small kernel additions (activity counter, foreground job) feed it. The API handlers read Facts and the Store snapshot.

**Tech Stack:** Elixir 1.20 / OTP 29 (`:re` = PCRE2), hex `toml ~> 0.7` (already a dep), `file_system` (already in herdr_reload), Rust NIF crate `dynide/native/dynide_kernel` (libc).

**Spec:** `docs/dynide/milestones.md` M11, the M11 brief (scope items 1-7, copied into "Scope decisions" below), `docs/dynide/design.md` (split, state layout, hot reload, "PCRE on manifest regexes"), reference behaviour in tag `herdr-reference`: `src/detect/manifest.rs`, `src/detect/mod.rs`, `src/pane/agent_detection.rs`, `src/pane.rs` (detection loop ~L960-1300), `src/pane/osc.rs` (AgentOscStateTracker), `src/terminal/state.rs` (hook authority), `src/app/api_helpers.rs` (`pane_agent_status`), `src/app/actions.rs` (`apply_pane_state_change`, seen), `src/cli/agent.rs` (explain text), `src/api/schema/agents.rs` (AgentInfo).

## Scope decisions (owner rulings, recorded in results/m11.md)

1. Manifests copied verbatim from `herdr-reference:src/detect/manifests/*.toml` to `dynide/apps/dynide_server/priv/detect/manifests/` (priv: shipped with the app, found by `Application.app_dir/2`). Local overrides: `<dir of HerdrServer.Config.path()>/agent-detection/<label>.toml` (herdr: `config_dir/agent-detection`). herdr's remote manifest download (`manifest_update.rs`, `server update-agent-manifests`) is dropped: herdr-live has no update channel (M18).
2. Source precedence: local override > bundled. A bundled manifest that fails to parse/compile disables only that agent's manifest (entry carries `error`), the known agent then falls back to idle (`default_known_agent_idle_fallback`, as herdr does with no manifest). An override that fails falls back to bundled with a `warning` (herdr's text: `ignored override <path> because ...`).
3. Engine in Elixir, `:re` compiled with `[:unicode, :ucp]`, run with `[{:match_limit, 200_000}, {:match_limit_recursion, 10_000}]`; a limit hit counts as no match and is reported in explain. Kernel fallback only if the engine misses its budget: p95 <= 2 ms per pane poll (120x40 screen, claude manifest). Measure first (Task 3), build nothing if met.
4. Detection source = plain text of the bottom `rows` rows of the active screen (`Kernel.vt().read_text(vt, {:rows, total - rows .. total - 1})`, total/rows from `scrollbar/1`), never the user viewport. OSC evidence = `Pane.Facts` `title` and `progress` (M9), treated as "" after an agent change until they change (herdr `clear_retained`; ceiling: an identical title from the new agent is ignored until it changes).
5. Polling: one `Detect.Poller` process, tick 300 ms (100 ms while any pane has a pending idle confirmation). Per tick: one `foreground_pgid` ioctl per pane (cheap), a job probe only when the pgid changed or a probe is due (Task 6), a text read + engine run only for panes with an identified agent whose kernel activity counter moved since the last scan or that have a due timer, at most `@scan_cap 4` scans per tick, round robin by pane id. Hidden panes are polled too (they parse; the activity counter is kernel-side).
6. Hook reports (`pane.report_agent`, `pane.release_agent`) are served because the user's installed herdr integrations (codex hooks, opencode plugin) already call them through `HERDR_SOCKET_PATH`. Precedence (herdr `terminal/state.rs`, simplified): a hook report for the pane's agent sets hook authority; effective state = hook state, except a screen `visible_blocker` overrides a non-blocked hook state; authority clears on `release_agent`, agent change or agent exit. herdr's stale-session bookkeeping is dropped (ponytail ceiling, noted). `pane.report_agent_session` is M17's (D6) and untouched.
7. `done` = herdr `pane_agent_status`: idle and not seen. A working/blocked -> idle transition stores `:done` unless the pane is in the active tab of the active workspace; making a tab active turns its `:done` panes `:idle`.
8. Integration install/uninstall and the settings `integrations` section are deferred (no installer in scope; existing herdr installs already work through decision 6). Go-to agent filters only if M17's `Modal.Goto` is on `herdr-live` when Task 10 starts; else noted for the coordinator.
9. Agent resume (M17 D6): M11 provides the agent label in `App.Session` pane meta `:agent` and in the Facts `{:agent, id}` row. Nothing else.

## Review Focus

1. A bundled or override manifest with a regex `:re` cannot compile, or a pathological regex on a 2000-char line: only that manifest is disabled / the match is a no-match, the poller never crashes or stalls (tests in Tasks 1 and 2).
2. A pane closes while the poller holds its tracker, or the Store/Pane.Server restarts mid-tick: the tracker and `{:agent, id}` row are dropped, no crash (Task 6 test `closed pane drops its tracker and facts row`).
3. An agent exits back to the shell: the state goes idle (herdr publishes idle with `process_exited`), the agent label clears after 6 missed probes, no stale `working` badge (Task 5 test `agent exit publishes idle then clears the agent`).
4. Alt-screen agents (opencode) and a scrolled-back viewport: detection reads the active screen's bottom rows, not the viewport (Task 6 test `scrolled viewport does not change the detection source`).
5. Working -> idle flicker: plain idle after working is held for 3 confirmations at 100 ms (cap 700 ms), visible idle passes at once (Task 5 tests).

  - `effective(t) :: :idle | :working | :blocked | :unknown` — hook state unless `t.visible.blocker` and hook state != :blocked; else `t.state`.
