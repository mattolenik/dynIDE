# M7 self-hosting loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** herdr-live becomes the terminal it is developed in: standalone daily driver
through `bin/herdr-live`, reload and handoff state visible in chrome, an optional
test-on-save gate, greppable crash and reload telemetry with a summary script, the Rust
reference tree pruned, and a dogfooding kit for the human's week.

**Architecture:** Telemetry is one line format written through `Logger` (VMs) and the
broker's `log!` (Rust), both into `$HERDR_LIVE_LOG`; a Python script summarises it.
Runtime status (last reload batch, test result, handoff) is a server fact held by
`HerdrServer.ReloadNotices`, mirrored in ETS, copied into each `Client.State` like the
existing `notice`, and rendered by `View.compute` as `:text` status children with ids
`:reload` and `:handoff` (no `HerdrScene` change). Test-on-save is a gate in front of
`HerdrReload.Server.reload/1` that runs `mix test` for the changed files in a separate OS
process before the in-VM compile.

**Tech Stack:** Elixir 1.20 / OTP 29 umbrella (`dynide/`), Rust broker
(`dynide/native/dynide_broker`), Python 3 harnesses, `just`.

**Spec:** M7 owner brief (coordinator scratchpad, items 1-8 quoted in Global Constraints),
`docs/dynide/milestones.md` M7, `docs/dynide/adr/0001-slice-1-gate.md` ("M7 must
do first" 1-4), `docs/dynide/design.md` (Goal, Hot reload), `AGENTS.md`.

## Telemetry line format (shared by Tasks 2, 3, 4, 6, 7, 8)

One event per line, anywhere in the line (after the Logger or broker prefix):

```
herdr-event <kind> ts=<unix epoch ms> k=v k=v ...
```

- Values matching `^[A-Za-z0-9_.:/@+-]*$` are bare; anything else is double-quoted with
  `\"` and `\\` escaped, newlines replaced by spaces, and truncated to 300 bytes.
  Lists (module names) are comma-joined, without the `Elixir.` prefix.
- Kinds and their required keys (extra keys allowed):

| kind | emitted by | keys |
|---|---|---|
| `vm_start` | `HerdrServer.Application` after start | `gen` `role` (`primary`) `adopt` (`fresh`/`crash`/`graceful`) |
| `vm_stop` | `HerdrServer.Application.stop/1` | `gen` |
| `reload` | `HerdrReload.Notices` on `{:loaded, ...}` | `batch` `fanout` `modules` `compile_ms` |
| `compile_error` | on `{:compile_error, diags}` | `file` `line` `count` `msg` |
| `rollback` | on `{:rolled_back, ...}` | `batch` `fanout` `modules` `reason` (`manual`/`raise`/`throw`/`exit`/`timeout`/`local_fun`/other) `detail` |
| `rejected` | on `{:rejected, mod, path}` | `module` `path` |
| `purge_blocked` | on `{:purge_blocked, ...}` | `module` `holders` |
| `sync` | `HerdrReload.Server` promotion sync | `count` `modules` `failed` |
| `tests` | test gate | `result` (`passed`/`failed`/`error`/`none`) `files` `failures` `ms` |
| `guard_failure` | `HerdrReload.Guard` logged failure | `mfa` `kind` `attributed` (batch id or `none`) `detail` |
| `handoff` | `HerdrServer.Handoff.Notice.broadcast/1` | `phase` `gen` `panes` |
| `crash` | Store restart from mirror, session crash, local client crash | `proc` (`store`/`session`/`local_client`) `reason` `action` (`restored`/`restarted`/`gave_up`/`none`) |
| `broker_handoff` | broker, every completed handoff | `kind` (`crash`/`graceful`) `from` `to` `entries` `ms` |
| `broker_handoff_failed` | broker, failed attempt | `reason` `from` `to` |
| `session_lost` | broker `fallback_restore` (children not carried) | `reason` `gen` |
| `broker_vm_exit` | broker, VM died or exited | `gen` `status` `role` |
| `broker_start` / `broker_stop` | broker run start / clean stop | `pid` |

A "session loss" for the dogfooding exit criterion is a `session_lost` line, or a
`crash proc=store action=restored` that the summary reports separately as a layout reset.

## Review Focus

1. A telemetry value with spaces, quotes, newlines or a multi-KB compile message: the line
   stays one line and parses back (Task 2 property-style test, Task 3 parser test).
2. Test-on-save with the child `mix test` inheriting `HERDR_BROKER_SOCK` / `HERDR_LIVE_*`:
   it must not connect to the running broker or touch the live control socket (Task 5
   test asserts the child env is scrubbed).
3. A local client that crashes in a loop (bad `Render` edit that raises in init): restarts
   stop after the limit, the tty is left cooked, the VM keeps running (Task 6 test).
4. Status line at 80 cols with a long tab list, a reload node, a handoff node and a notice:
   no overflow, hint still visible, nodes dropped in priority order (Task 4 test).
5. The prune removing a file the kernel crates, vendor scripts or `dynide/` still use:
   `cargo build` at root, every `live_crates` build, `just maintenance-test` and
   `just live-check` stay green (Task 1 verification, again in Task 11).
