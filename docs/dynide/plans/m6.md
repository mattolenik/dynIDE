# M6 slice-1 gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce the numbers that decide whether the herdr-live architecture holds (slice-1 metrics table, macOS and Linux, three runs each), fix or classify every miss, and write a proposed gate ADR.

**Architecture:** Mostly measurement. Existing harnesses (`just live-bench`, `live-bench-reload`, `live-bench-handoff`) are reused; M6 adds only what the table needs and nothing measures yet: a herdr reference (keystroke→glass through a real pty for both binaries, herdr's own `render_scale_profile` for the frame ratio), a `--size` flag so herdr-live's frame bench runs at herdr's geometry, a second-client latency row, and a Linux container runner. Misses get a root cause and exactly one of (a) bounded fix with regression test, (b) design.md change marked `(M6 gate change)`, (c) no-go.

**Tech Stack:** Elixir 1.20.4 / OTP 29 umbrella in `dynide/`, Rust NIF crates, python3 stdlib pty harness, podman (`podman-machine-default`, 6 CPU / 8 GiB).

**Spec:** `docs/dynide/design.md` ("Slices and go/no-go", slice-1 table), `docs/dynide/milestones.md` M6, the M6 owner brief (scratchpad `m6-brief.md`), `docs/dynide/results/m1.md`..`m5.md`.

## Global Constraints

- Everything in `AGENTS.md`: no OS branches in Elixir, no `unwrap()` in Rust production code, Guard boundaries unchanged, `consolidate_protocols: Mix.env() == :prod`.
- Do not change `HerdrScene` or the client protocol for a fix; a miss needing that is a (b) item.
- Never edit `docs/dynide/status.md` or `milestones.md`. design.md changes only as (b) items marked `(M6 gate change)`.
- Benches never run in parallel with each other or with a Linux build on the same host. Never kill processes by name pattern; kill only pids/process groups you started.
- Every recorded number carries: commit, OS/hardware, load average at start and end.
- Branch `live/m6` in `../herdr-live-worktrees/m6`; commit freely (lowercase conventional, no co-author); never push.
- No new dependencies (Hex, crates, pip).

## Review Focus

- Herdr reference binary emits terminal probes (DA1, kitty `?u`, OSC 10/11, XTVERSION) and may stall waiting for replies: the pty harness must answer the probes `tty_harness.py` answers and must not count a probe-reply wait as latency (measure only after first frame and quiescence). Test: Task 1 step "glass smoke" asserts both binaries reach a `cat` prompt and give >= 50 samples with no timeout.
- A redraw unrelated to the keystroke (status clock, cursor blink) counted as the echo: harness waits for idle (no output 30 ms) before each key and matches the typed char inside the next output burst. Test: Task 1 harness self-check feeds a recorded burst without the char and expects no sample.
- Linux container runs mix/cargo against macOS `_build`/`target` artifacts: runner copies the tree excluding `_build`, `deps`, `target`, `priv/native`, `.git`. Test: Task 2 runner prints `uname -s` = Linux and builds from clean.
- `--size` frame bench given a geometry too small for 15 panes: fail with a clear message, not a crash deep in Layout. Test: Task 1 bench smoke with `--size 20x5 --quick` exits non-zero with "too small".
- Standby promoted after a source edit (ruling 28) runs stale code silently: Task 5 measures it with a script that edits, kills the primary, and checks the marker.
