# M8 persistence and session restore Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** layout, tabs, workspaces, focus and per-pane metadata (cwd, title, command,
hidden) survive a full stop/start of `bin/herdr-live`; the last N rows of each pane's
history come back above the new shell's prompt (ADR 0002).

**Architecture:** A pure `HerdrServer.Persist.Schema` maps the app (`App.Session`,
`App.Focus`, `App.Ui`) plus per-pane runtime facts to an explicit, versioned plain-term
snapshot and back. `Persist.Disk` owns paths and atomic ETF files. `Persist.Facts` reads
runtime facts from the kernel (shell cwd via a new `pty_cwd` NIF, command from the keeper
row, history via a new `vt_tail_ansi` NIF). `Persist.Writer` polls the ETS mirror once a
second and writes only on change, plus scrollback on a slower cadence and a final write
on clean stop. `App.Store.init` restores from disk when there is neither a broker carry
nor a mirror (precedence carry > mirror > disk). The broker's `fallback_restore` sends
FRESH with a reason byte so the VM records `reason=fallback`.

**Tech Stack:** Elixir 1.20 / OTP 29 umbrella (`dynide/`), Rust NIF crate
`dynide/native/dynide_kernel` (libghostty-vt via `crates/ghostty-vt`), Rust broker
`dynide/native/dynide_broker`, Python 3 harness and `log_summary.py`, StreamData (test only).

**Spec:** M8 brief (coordinator scratchpad `m8-brief.md`, items 1-5 restated under Global
Constraints), `docs/dynide/milestones.md` M8, `docs/dynide/design.md` (State
layout, Hot reload, "What hot reload does not cover"), `docs/dynide/results/m5.md`
rulings 4, 13, 17, 27 and "Notes for M8", `AGENTS.md`.

## Global Constraints

- Branch `live/m8`, worktree `../herdr-live-worktrees/m8`. Never push. Never edit
  `docs/dynide/status.md` or `milestones.md`. Lowercase conventional commits, no
  co-author lines, explicit paths.
- M8 owns `HerdrServer.Persist.*`, startup restore in `App.Store` init, schema
  versioning, the broker `fallback_restore` hook. `App.Store.Carry` and
  `App.Store.Mirror` stay as they are. Shared files (`App.Store`, `Application`,
  `Native.Keeper`, kernel behaviours/fakes, `Handoff.Link`) get small additive edits only.
- No `HerdrScene` or client-protocol change (none is needed: no SPEC_PUBLISHED).
- Snapshot file: `<dir>/session.<name>.etf`, `dir` = `$HERDR_LIVE_STATE_DIR`, else
  `${XDG_STATE_HOME:-$HOME/.local/state}/herdr-live`; `name` = `$HERDR_LIVE_SESSION`
  (default `default`, must match `^[A-Za-z0-9_.-]{1,64}$`, else `default` and a warning).
  Atomic writes: temp file in the same dir, `:file.sync`, rename. Files mode 0600.
- Persistence is on only when `HERDR_BROKER_SOCK` is set (a `bin/herdr-live` VM), not in
  `:test`, and `HERDR_LIVE_PERSIST` is not `0`. Tests start a Writer explicitly.
- No local funs ever reach disk: the schema holds only integers, floats, binaries,
  booleans, nil, atoms named in `Persist.Schema`, lists, tuples of those and maps.
  `Schema.plain?/1` checks it before every write.
- Restore spawns `$SHELL` (as today's `{:spawn, ...}` effect does) in the recorded cwd;
  the recorded command is metadata and is never re-run.
- Keybinds are not persisted: restore uses `Keybinds.default()`. `App.Focus.modal` is
  not persisted (restored as `[]`).
- No compile-time dependency from `Persist.*` on `App.Session`/`App.Ui`/`App.Focus`
  struct literals (use `struct/2` at runtime, map access), so the reload bench fan-out
  for "add a field to `App.Session`/`App.Ui`" stays 2 and 3.
- Telemetry via `HerdrReload.Telemetry.event/2`, kinds `persist_write`,
  `persist_restore`, `persist_error`; `k=v` fields only.
- Rust: no `unwrap()` in production code, `#[cfg]` on items for platform code, no new
  crate dependency. Kernel thread rules unchanged (the new NIFs are bounded calls).
- New Elixir dependency: `{:stream_data, "~> 1.1", only: :test}` in `herdr_server`
  (justified in its commit: generating valid apps for the fixed-point property).
- `just live-check` and `just maintenance-test` green on macOS; `dynide/scripts/linux_check.sh
  'just live-check && just maintenance-test'` (image tag `herdr-m8-check`, volumes
  `herdr-m8-cargo`/`herdr-m8-hex`) green once before hand-back. `just live-bench-reload`
  meets its targets; frame bench at 15 panes within 10% of M7 (338/379 µs).
- Shared host: never kill processes by name pattern; benches one at a time, load average
  recorded with every number.

## Review Focus

- A recorded cwd deleted between stop and start: the pane opens in the nearest existing
  ancestor (else the VM cwd), never fails to spawn. Test in Task 5.
- A corrupt, truncated, wrong-format or newer-version session file: the VM starts with a
  fresh app, the file is moved aside (`.bad-<ms>` / `.v<N>-<ms>`), no crash, one
  `persist_error`. Tests in Task 3.
- An old VM after RELEASE (or during PREPARE) writing its stale app over the new VM's:
  the Writer never writes while `Protocol.handoff_key` is `:begin` or `:released`,
  including in `terminate/2`. Test in Task 4.
- Smokes, harness and benches clobbering or restoring the human's dogfood session: every
  `bin/herdr-live` launch in scripts and benches sets `HERDR_LIVE_STATE_DIR` under its
  temp dir. Test (grep assertion) in Task 8.
- Unwritable state dir or full disk: the Writer logs `persist_error op=write` once per
  distinct reason, keeps running, retries next change. Test in Task 4.
