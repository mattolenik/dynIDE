# M16 Remote Attach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** attach a `herdr_term` client running in its own VM to a herdr-live server over a unix socket, locally or through SSH, with reconnect, a grace period, and kernel restarts that keep the client attached.

**Architecture:** a server-side connection process (`Client.Remote`) per socket client stands in for the client pid that `Client.Session` already talks to; it frames ETF over the socket, batches and diffs `{:inline, rows}` per frame, dedups input across reconnects, lingers for a grace period, and hands its socket fd to the broker (`client/<id>`) so a new VM adopts it. A client-side twin (`HerdrTerm.Remote.Conn`) stands in for the endpoint and session that `Render`/`Input` already talk to, over a unix socket or an `ssh host herdr-live attach-relay` port. `Client.Session`, `View` and `Compose` do not change.

**Tech Stack:** Elixir 1.20 / OTP 29 umbrella, `:gen_tcp` local sockets (`{:packet, :raw}`, framing in Elixir), Rustler NIF (`herdr_kernel`) for two fd helpers, `herdr_broker` HOLD/UPDATE/DROP, OpenSSH client.

**Spec:** `docs/dynide/milestones.md` (M16), `docs/dynide/design.md` ("Client protocol", "Protocols and remote"), M16 brief (scope 1-7, copied into "Scope" below), `results/m5.md` (ruling 15, notes for M16), `results/m12.md` (deferred rows).

## Scope (from the brief, decisions already made)

1. Length-prefixed ETF frames (`binary_to_term(.., [:safe])` both ends) over a unix socket `client.sock` beside the API socket; SSH via stdio piping; never epmd or distribution. Auth: 0700 dir + per-server token file read over SSH. Threat model in results.
2. `{:inline, rows}` for socket clients: packed rows, `{:rows, pane_id, gen, [{n, bin}]}` batched per frame per client; hidden/off-screen panes send nothing; measure bytes/s for the 15-pane cat flood and typing latency (loopback and `ssh localhost`).
3. Remote client = `herdr_term` in its own VM with a socket transport; `herdr-live attach [<host>] [<session>]`; no host = local socket.
4. Dropped socket: server session alive for a grace period; client retries with backoff; client-local failures give client-local notices and never disconnect other clients.
5. Handoff: `:begin`/`:released` hold input, reconnect after `:adopted`; sockets HELD under `client/` and claimed with `Handoff.Link.take_adopted/1` before `restored/0`; fall back to reconnect.
6. `session.snapshot`, session discovery, terminal attach/observe verbs through `Api.Spec`.
7. `herdr-event client_*` telemetry and a `log_summary.py` section.

## Decisions (rulings, recorded in results/m16.md)

- R1 Paths: `client.sock` and `client.token` live in the API socket's dir: `$HERDR_LIVE_CLIENT_SOCK` else `dirname($HERDR_LIVE_API or default api.sock)/client.sock`; token `client.token` beside the socket, 0600, created once (32 random bytes, hex), kept across VMs. Computed by `HerdrScene.Wire.paths/1` from an env map so server, term client and CLI agree.
- R2 Auth: the first frame on every connection is `{:auth, token}`; the relay (`attach-relay`, run on the server host over SSH) reads the token there and sends it, so the token never crosses to the client machine. Local attach reads the file itself. Wrong/missing token: `{:refused, "bad token"}` then close.
- R3 Wire vocabulary in `HerdrScene.Wire` (pure, herdr_scene), published early (SPEC_PUBLISHED).
- R4 Inline rows in a scene become a partial update: listed rows replace those rows of the client's cache, unlisted rows keep it (blank when none). Doc change in `Scene.Pane` and `Protocol`, one-line merge in `Render`. This lets the server conn send only changed rows inside the scene.
- R5 Framing: `{:packet, :raw}` with Elixir-side `<<len::32-big, etf::binary-size(len)>>` parsing so a partial frame can be carried in the handoff blob. Max frame client→server 32 MiB (pastes up to 16 MiB plus overhead), server→client 64 MiB.
- R6 Client frames are decoded with `[:safe]`, rejected unless `HerdrServer.Persist.Schema.plain?/1` (no pids, refs, funs, ports), then validated. An invalid frame gets `{:notice, %{level: :warning, text: "frame rejected: ..."}}` and the connection stays; a frame over the size limit or undecodable framing closes only that connection.
- R7 The client VM preloads every module of `herdr_scene`, `herdr_reload`, `herdr_term` before connecting (as M5 ruling 23), so `[:safe]` knows the atoms. An architecture test asserts that every atom in server→client fixtures and live scenes exists in those apps' atom tables. A frame the client cannot decode is dropped with a client-local notice ("server sent a term this client cannot decode; same commit on both ends?").
- R8 Wire seq: the client conn renumbers each input to its own monotonic wire seq and maps acks back; the server conn forwards wire seq > `last_seq`, re-acks wire seq <= `acked`, drops the rest (exactly-once across reconnects within one session). After an adoption `last_seq := acked`.
- R9 Grace: a session-mode server conn whose socket closes lingers `grace_ms` (config `:herdr_server, :client_socket, grace_ms: 60_000`) keyed by `client_id` in `HerdrServer.Client.Remote.Registry`; a new connection with that id resumes it (`{:attached, %{resumed: true, ...}}` + full scene). Expiry stops it normally (session ends). Pane-mode conns do not linger.
- R10 Batching: `Client.Outbox` (pure) coalesces scenes and rows; flush when idle (last flush >= `frame_ms` ago) else after the remainder; `frame_ms` config default 8 (measured against 16 in the bench; the bench result may change the default). Other messages (ack, input_mode, notice, handoff, detached, clipboard, bell, open_url, alert) flush pending scene/rows first, then go at once, in arrival order.
- R11 Handoff: a session-mode conn HOLDs `client/<client_id>` (blob = `term_to_binary(%{v: 1, client_id, info, acked, buffer})`, fd = dup of the socket) right after attach, UPDATEs on prepare, DROPs before any server-initiated close and at grace expiry. `Handoff.Link` on PREPARE (after `Store.flush_hold`, before `Keeper.prepare`) calls `Client.Remote.prepare_all/0` (each conn: passive, drain `{:tcp,..}` from mailbox into its buffer, flush outbox, wait up to 200 ms for `send_pend == 0`, UPDATE, freeze: no reads, no writes) and terminates `Client.Socket`; THAW: `Client.Remote.thaw_all/0` then restarts `Client.Socket`. New VM: `Client.Socket.init` claims `take_adopted("client/")` and starts one adopted conn per entry (`:gen_tcp.fdopen/2`), which attaches a new session with the blob's info, sends `{:attached, %{resumed: :handoff}}` and a full scene. A blob that does not decode or a buffer over 1 MiB: `unclaim`, close fd (client reconnects).
- R12 Client conn on `{:handoff, %{phase: p}}` with p in `[:begin, :released]`: hold (queue input, send nothing); `:aborted`: release; any `{:attached, _}`: release and resend unacked in wire order.
- R13 Transport on the client: no host → `:gen_tcp` local socket; host → `Port.open({:spawn_executable, ssh}, [:binary, :exit_status, args: [...]])`, ssh = `$HERDR_LIVE_SSH` (split on spaces) else `ssh`, args `-T -o BatchMode=yes -o ServerAliveInterval=10 -o ServerAliveCountMax=3 <host> <remote_bin> attach-relay`, `remote_bin` = `$HERDR_LIVE_REMOTE_BIN` else `herdr-live`. BatchMode always: attach needs key or agent auth (documented).
- R14 Backoff: 100 ms doubling to 5 s, reset after an attach succeeds. While disconnected the client conn shows a client-local notice by rewriting the last scene's `:status` node child `:notice` (`HerdrTerm.Remote.Notice.put/2`), and clears it on attach.
- R15 Detach: `{:detached, _}` ends the remote client VM. `Tty.Owner` gets option `remote: true`: tty gone or detached call `Client.local_exit/1` (System.stop), handoff is ignored (only `local: true` releases the tty on `:begin`).
- R16 Session discovery: one session per instance (`HERDR_LIVE_SESSION`, default `default`). `attach <host> <session>` sends `session` in the attach frame; a mismatch is `{:refused, "no session <x> here (this server runs <y>)"}`.
- R17 Terminal verbs: `herdr-live terminal observe <pane_id> [--host H]` and `terminal attach <pane_id> [--host H]` attach the same remote client with `target: {:pane, id, :observe | :control}`. The server conn does not start a `Client.Session`: it registers in `HerdrServer.Client.Registry` `:clients`, follows `{:pane_damage, id, _}` for its pane, builds a one-pane scene with `Client.PaneScene.build/3`, and in `:control` writes keys/paste/mouse straight to `Pane.Input`. Observe drops input (acks it). The client handles `ctrl+b q` (detach) and `ctrl+b ctrl+b` (literal) itself in pane mode. Pane closed: `{:detached, :pane_closed}`. Pane size is the layout's; the client clips/pads. No PTY bytes, no ANSI on the server.
- R18 Client VM: `bin/herdr-live attach|terminal ...` runs `mix run --no-halt --no-start -e 'HerdrTerm.Remote.main(System.argv())' -- <args>` from `dynide/` with `HERDR_LIVE_HEADLESS=1`, stdio to `$HERDR_LIVE_CLIENT_LOG` (default `client.log` beside the server log default), reload disabled in that VM (`Application.put_env(:herdr_reload, HerdrReload, enabled: false)` before start).

## Review Focus

- A client that disconnects mid-frame (partial length prefix or partial body): the server conn must not crash or desync the next connection; tested in Task 4 (`partial frame then close`).
- A paste larger than 1 MiB over the socket: delivered intact as one `{:paste, bin}`; tested in Task 4 (`2 MiB paste`).
- Server restarts the Store while a socket client is attached: the client keeps working (Session already follows the Store; the conn must not die); tested in Task 6 integration (`store restart keeps the remote client`).
- Two remote clients with the same `client_id` (a copied state): the second resumes and the first's socket is closed with `{:detached, :replaced}`; tested in Task 4.
- Slow client (socket write blocks): other clients' frames are not delayed; the slow conn coalesces instead of queueing unboundedly; tested in Task 4 (`blocked reader does not stall another client`).
