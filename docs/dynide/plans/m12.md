# M12 API and CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a newline-delimited JSON socket API and a `herdr-live <verb>` CLI over it, so
automation and agents (including one running inside a herdr-live pane) can open, split,
close and focus panes, tabs and workspaces, send keys and text, read pane text, and
subscribe to events; the M4 `HerdrServer.Control` socket is folded in and deleted.

**Architecture:** `HerdrServer.Api.Spec` is the single source of truth: a list of method
specs (params, result type, error codes, CLI form). It validates params, validates
results in tests, and generates `docs/dynide/api.md`. `HerdrServer.Api.Listener`
owns the unix socket (the locking rules move over from Control) and spawns one linked
`Api.Conn` per connection; `Conn` frames lines, decodes JSON and calls
`Api.Router.handle/3` through `HerdrReload.Guard` (editable code behind the guard).
Topology changes are pure functions in `HerdrServer.App.Commands` run through a new
`App.Store.request/1` that replies `{:ok, before, after}`; handlers derive results from
the two apps. Events come from `Api.Events` (a hub subscribed to the Store's
`{:app_changed, app}`) and a pure `Api.EventDiff`. The CLI is a new umbrella app
`herdr_cli` (`HerdrCli.*`, no server deps), started by `bin/herdr-live` with `erl -pa`
(choice measured in Task 7).

**Tech Stack:** Elixir 1.20 / OTP 29 umbrella (`dynide/`), Elixir's built-in `JSON`
module (no new dependency), `:gen_tcp` local sockets, POSIX sh launcher, Python 3 tty
harness, `just`.

**Spec:** M12 brief (coordinator scratchpad `m12-brief.md`, quoted in Global
Constraints), `docs/dynide/milestones.md` M12, `docs/dynide/design.md` (The
split, Client protocol, Protocols and remote), `AGENTS.md`, herdr reference CLI/API
(`git show herdr-reference:docs/next/website/src/content/docs/cli-reference.mdx` and
`socket-api.mdx`), M5 ruling 29 (`results/m5.md`).

## Global Constraints

- Branch `live/m12`, worktree `../herdr-live-worktrees/m12`. Never push. Never edit
  `status.md` or `milestones.md`. Lowercase conventional commits, no co-author lines,
  commit explicit paths.
- M12 owns `HerdrServer.Api.*`, the CLI in `dynide/bin/dynide`, `HerdrCli.*`, and
  deletes `HerdrServer.Control`. Shared files (`App.Store`, `App.Actions`,
  `Handoff.Link`, `config/*.exs`) get small additive edits only.
- No `herdr_scene` change in this plan (the API is JSON, not scene vocabulary), so no
  SPEC_PUBLISHED is needed. If a task finds it needs one, stop and report.
- Socket: `$HERDR_LIVE_API`, else `${XDG_STATE_HOME:-~/.local/state}/herdr-live/api.sock`
  (empty env counts as unset); default dir created 0700, socket chmod 0600; exactly
  Control's rules for stale sockets, live sockets, non-socket files, missing custom
  dirs and paths over 103 bytes (run without a socket, log, never fail app start).
- `HERDR_LIVE_CONTROL` is renamed `HERDR_LIVE_API` everywhere (launcher, smokes,
  harness, bench driver, `config/runtime.exs`, `HerdrReload.TestGate` unset list).
- The API moves with the primary across a handoff exactly as Control did (ruling 29):
  `Handoff.Link` terminates the `HerdrServer.Api.Listener` child after the freeze on
  PREPARE and restarts it on THAW. Open connections close with it.
- Wire: one JSON object per line, UTF-8, max line 1 MiB. Request
  `{"id": string, "method": string, "params": object?}`. Success
  `{"id", "result": {"type": string, ...}}`; error
  `{"id", "error": {"code", "message", "data"?}}`. Unparseable line or no string `id`:
  `"id": ""`. Several requests per connection, answered in order.
- Error codes (closed set): `parse_error`, `invalid_request`, `unknown_method`,
  `invalid_params`, `not_found`, `not_available`, `failed`, `timeout`, `backpressure`,
  `events_lost`, `internal`.
- Public ids: workspace `"w<N>"`, tab `"w<N>:t<M>"`, pane `"p<K>"` (K is the global
  `App.Session` pane id). Only this form is accepted.
- Classification: shared runtime facts (pane/tab/workspace metadata, process state,
  terminal text, events) are in the API; presentation state (selection, hover,
  per-client viewports, colours, chrome) is not. Names neutral: no sidebar/row/widget.
- Agent methods (`agent.list|get|read|explain|wait|prompt|send_keys`) exist with full
  param specs and always return `not_available` with
  `data: {"requires": "M11 detection"}` until M11.
- Telemetry via `HerdrReload.Telemetry.event/2`: `api_connect` (`conns=<open count>`),
  `api_denied` (`method`, `code`: refused before a handler ran: `parse_error`,
  `invalid_request`, `unknown_method`, `invalid_params`, `not_available`),
  `api_error` (`method`, `code`, `msg`: a handler ran and failed: `internal`,
  `timeout`, `backpressure`, `events_lost`). `not_found` and `failed` are normal
  answers and log nothing.
- In `MIX_ENV=test` the Listener is not started by the application
  (`config :herdr_server, :api, enabled: config_env() != :test`); tests start their own
  with a tmp `path`. Reload verbs answer `not_available` when
  `:herdr_reload, HerdrReload, :enabled` is false.
- No new dependency. JSON through Elixir's `JSON` module.
- Measure: CLI startup latency (Task 7), `just live-bench-reload` targets and the
  15-pane frame bench within 10% of `results/m7.md` (Task 9), load average with every
  number.
- `just live-check` and `just maintenance-test` green on macOS; `dynide/scripts/linux_check.sh`
  with image `herdr-m12-check`, volumes `herdr-m12-cargo`/`herdr-m12-hex`, once at the end.

## Review Focus

1. A CLI call during a graceful handoff (socket gone for a few ms) should retry and
   succeed, not print "not running". Pinned in Task 7 (`retries a missing socket`).
2. A pane closed between snapshot and command (agent races the user) answers
   `not_found`, never `internal`. Pinned in Task 4 (`split of a pane closed meanwhile`).
3. A slow event subscriber must not grow memory without bound: past 1000 queued
   events it gets `events_lost` and is closed. Pinned in Task 6.
4. `send-keys` with an unknown key name sends nothing at all (validate every key
   before writing any byte). Pinned in Task 5.
5. A pane exiting in a non-active workspace is removed from its layout (today
   `{:pane_exited, id}` only looks in the active workspace). Pinned in Task 2.
